# OBS 4K/60fps の再検証と修正

## 要件

ユーザー指定: 受信アプリはOBS、最大3840×2160・60fps。会話の蓄積に引きずられず、一度整理して検証・実装する。既存のFreeze・シーク追従を維持する。

## Global Constraints

- 基準コミットは01c6b1a。製品のデコード既定を説明なしに変更しない。
- 現在のコード・DLL・新しい実測を根拠にする。過去の報告は再現手順の参考で、根本原因の証明ではない。
- OBSの既存シーン・設定・ユーザーの作業を保護し、専用の検証用設定を使う。配信しない。
- 実機アプリ、音声、GPU負荷を伴う実行とビルドはrootが単独で管理する。
- 新しい担当者には会話履歴を渡さない。読み取り調査は並行可、製品実装は一担当者ずつ。
- 確認できない全フレーム精度・性能・メモリ安全性を合格としない。
- AGENTS.md、既存の測定証跡、他アプリのプロセスを削除しない。コミットは日本語。

## Task 1: 基準の固定と独立調査

残留プロセス・物理メモリ・OBSとSpout受信機能を確認する。履歴を渡さない独立担当者がSpout送信の境界とGPUデコードから画像公開までを読む。変更点・仮説・未確認事項を分離する。

## Task 2: 最小再現と実装修正

調査で特定した一つの原因について、既存同期・映像デコードの影響を分離できる最小再現を先に作る。同じ条件で失敗を確認後、必要最小限の製品修正と回帰テストを実装する。原因が未確定なら追加観測を行い、設定切替で問題を隠さない。

## Task 3: OBS検証とレビュー

OBSを専用設定で4K/60fps受信させ、通常再生・シーク・Freeze/Blackを確認する。実画像の整合、更新、処理負荷を区別して記録する。既存の関係するテストと独立コードレビューを行い、達成事項と残課題を報告する。
