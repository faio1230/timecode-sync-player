# 指示書: K3 の残り 1 件（F-4 の 4 回目 f4-14、時間切れなしで絵が違う）の原因の調査

作業ツリー `timecode-sync-player-v053`、ブランチ `agent-a-v054`（`563b962`。v0.5.4 に取り込み済み）。
**調査だけ。製品コードと shim は変更しない**（修正の方針は報告を見て親と TSP-Fable が決める）。

## 事実

- `docs/design/v0.5.4-k3-a1.md` の §9〜§12。§12: 修正後、ギャップの Freeze 336 回で最終フレームの取り込みの時間切れは 0 回。
  ただし F-4 の 4 回目（`artifacts/analysis-data/k3v-f4c15-4`）の f4-14 で、最終フレームのはずの絵が M3 の先頭のまま
  （位置 20.017）。時間切れは出ていない。
- 前任（上限で停止）の最後の仮説: 一時停止のポンプ（pump tick）が、目標のフレームの publish と同じ ms に PAUSED にしており、
  復号または GPU のコピーの途中で止めたため、目標の PTS を持つが中身が古いテクスチャが配信された。ほかの成功した回では
  ポンプの tick が数 ms 遅く、復号が終わっていた。確かめる候補: 共有リングのフェンス（ring fence）が、この配信で
  コピーの完了を待っていたか。

## やること

1. `k3v-f4c15-4` のアプリのログ・shim のログ・試験の結果から、f4-14 の前後の時系列（シークの発行、世代、publish、
   PAUSED、取り込みの確定、配信した PTS、フェンスの値）を表にする。成功した近い回（同じ手順の f4-13・f4-15、
   ほかの回の f4-14）と並べて差を示す
2. 前任の仮説を、ログとコード（`native/gst-shim/src/tcs_gstreamer.cpp`、`Output/` の取り込みとフェンス）で
   確かめるか否定する。否定されたら別の説明を探す。**推測と事実を分けて書く**
3. 仮説が当たっていた場合の直し方の候補を 1〜3 案（shim のロックの規則 I13 を守ること、定数を足さない案を優先）。
   各案で、ほかの経路（step、読み込み、S-load）に何が起きるかも書く
