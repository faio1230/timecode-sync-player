# D37-b: シーク中の再生位置を信用しない／実在の不足には速度補正で応じる

**D37-a の後に残った経路を塞ぐ。** 根拠はすべて実測。

---

## 1. D37-a で分かったこと

### 効いたこと

VP9 4K60（キーフレーム 10 秒）で補正シーク **0 / 0 / 0 回**、停止合計 **0 秒**、最大誤差 0.100〜0.107 秒。
既存シナリオ 22/22、LTC ループ 14/14、V3 も前日と同水準。

### 残ったこと

1. **シーク中の再生位置の問い合わせが信用できない。** 同じ run で理想直線からの残差の σ を測ると
   - LTC 側: 平常時 0.33ms / 連鎖中 0.36ms（**常に安定**）
   - **再生位置側: 平常時 0.00ms / 連鎖中 445ms**（最小 -781ms、最大 +567ms）
2. **実在の不足が育つ経路**。参考 run で、ゲートが初回の偽発火を抑止した後、
   誤差が 0.28 → 0.43 → 0.54 → 0.69 → 0.88 → 1.15 → 1.45 秒と**実際に増え続けた**
   （このときはシークが 7 回出た。ゲートのせいではなく、本物のずれ）

## 2. 直すこと

### 2-1. シークの着地が確認できるまで、位置を使う判定を止める

いまは保留が **2 秒の時間切れ**で解除され（`TimecodeSyncSeekState.cs:118-125`）、その後に暴れた位置を拾いうる。

- **着地が確認できるまで**（新しい位置のフレームが実際に届くまで）、粗い判定と補正の両方を評価しない
- 時間切れは残してよいが、**時間切れで解除した直後の数サンプルは判定に使わない**
  （位置が安定したことを確かめてから再開する）
- 「位置が安定した」の判定は、**位置の進みが実時間の進みと整合すること**で見る
  （連続する 2〜3 サンプルで、位置の増分が経過時間の ±20% 以内）

### 2-2. 実在の不足には、シークではなく速度補正で応じる

実測で、速度補正の実力は **93 ms/秒**（±10%）。着地窓では **200 ms/秒**（±20%）。

- 不足が育っているとき（＝位置が LTC に対して遅れ続けているとき）、**シークを出す前に速度補正に任せる**
- **任せる上限**を決める: 誤差が「シーク 1 回の実測所要」を超えるまでは速度補正。超えたらシーク
  （シークの所要は素材ごとに実測できる。学習した値が無い間は保守的に 1.0 秒を使う）
- 速度補正で詰めている間は、**その旨をログに残す**（何秒かけて何 ms 詰めたか）

**理由**: シークは「絵を 0.5〜2 秒止めて、止めた時間ぶんの誤差を作る」操作。
実測で、連鎖中は区間の **75% が完全静止**（同じ 1 枚を最大 1.78 秒）だった。
一方、速度補正は絵を止めない。**1 秒の不足なら、10 秒かけて滑らかに詰める方が現場では良い**（利用者と合意済みの方針）。

### 2-3. 触らないもの

- 許容値（6 フレーム）、Jump のしきい値（80ms）、Smooth の制御則、保持の明示着地、D37-a のゲート
- shim（今回はアプリ側だけ）

## 3. テスト

- 単体: 保留中・着地未確認の間は、粗い判定も補正も評価されない
- 単体: 時間切れ解除の直後、位置が安定するまで判定に使わない
- 単体: 不足が育つ系列で、シークの実測所要を下回る誤差なら**シークを出さず速度補正**を選ぶ
- 単体: 誤差がシークの実測所要を超えたら、シークを出す
- 既存の非E2E がすべて通ること

## 4. 実機での確認

1. **VP9 4K60（重い素材）で L-1 を 3 回**。補正シーク 0 回、停止合計 0 秒、最大誤差が D37-a と同水準（0.1 秒前後）を維持
2. **わざと不足を作る**（負荷をかける、または追従開始直後に大きくずらす）ケースで、
   **シークを出さずに速度補正で詰め切れるか**。詰め切るまでの時間と、その間の誤差の推移
3. 既存シナリオ 22 + LTC ループ 14
4. V3 を 1 本（同期精度の非回帰）
