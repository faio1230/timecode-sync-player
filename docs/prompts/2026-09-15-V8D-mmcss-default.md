## 依頼

### 1. MMCSS を既定で有効にする

- いまは環境変数で切り替える形（既定は無効）。**既定を有効に変える**
- **無効にする手段は残すこと**（`TCS_OUTPUT_THREAD_PRIORITY=off` など）。
  現場で問題が出たときに戻せる必要がある
- 既定値の変更なので、**設定の既定値を変えたことがログに残る**ようにしておくこと（起動時に 1 行）

### 2. 未検証だった 3 点を埋める

V8-C の報告で「未検証」と申告のあったもの。**既定で有効にする以上、ここを埋める必要がある。**

| 項目 | やること |
| --- | --- |
| **失敗経路** | `avrt` が無い／登録が失敗する環境で**アプリが落ちないこと**。実機で再現できないなら、ユニットテストに加えて「失敗時に通常の優先度で動き続ける」ことを E2E かログで示す |
| **強制終了時の revert** | プロセスを強制終了したあと、**MMCSS の登録が残って他のアプリに影響しないこと**。OS が自動で解除するなら、その根拠（ドキュメント等）を示せばよい |
| **長時間運転** | **V6 の 60 分連続運転に乗せて確認する**（V6 はどのみち必要）。60 分を通して落ちが基準内に収まるか、優先度が維持されるか |

### 3. 既定有効の状態で測り直す

**V8 の合否をこの構成で確定させる。** GStreamer 4K、50 秒、DISPLAY1 全画面、Spout ON。

- **3 本**回して、落ち（間隔 > 25ms）と**連続の有無**を出す
- **連続の判定**: 落ち同士が何枚離れているかも出すこと（V8-C では最小 25 枚 = 約 0.42 秒だった）
- UI 応答・LTC 受信・CPU が V8-C と同水準であることも確認
