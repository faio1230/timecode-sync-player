# v0.5.3 段 3a: BeginFileLoad を通らない読み込み経路の棚卸しと赤いテスト（w5:p3 向け、製品コードは変えない）

作業ツリーとブランチは、v0.5.2 の公開後に `main` から切る `v0.5.3`（親が用意して知らせる）。**製品コードは変えない。**
背景は設計書 `docs/design/v0.5.2-sync-state.md` の §6 の 2 と §3 段 3、段 0 の表 `LatchLifetimeTable.cs` の `FileLoadWithoutBegin` の行。

## 目的

v0.5.3 は寿命の食い違いを 1 件ずつ直す版で、最初が §6 の 2（`BeginFileLoad` を通らない読み込みでは、読み込み番号・ロード中・シークの保留・
位置の信頼などが初期化されない）。経路ごとに、直すと何が変わるか（とくにギャップの Freeze の取り込みの途中で状態が消えないか）を、
親が判断できる形にする。

## やること

1. `docs/design/v0.5.3-load-paths.md`（新規）に、`BeginFileLoad`（`BeginSyncFileLoad`）を通らないプレイヤーの読み込みを**すべて**表にする:

   | # | 経路（呼び出し元） | いつ起きるか | 位置つきか・一時停止か | 今 `BeginFileLoad` を通らないことで残るラッチ（段 0 の表の `FileLoadWithoutBegin` の 9 行から） | 通すようにすると変わる場面 |

   - 既知の候補: GPU 復旧（`MainWindow` の「GPU 復旧」）、Continue の自動送り（MediaIn > 0 の位置つき）、ギャップの `LoadPausedAt`（`GapPlaybackCommandExecutor`）、
     Freeze の取り込みの読み直し（`GapFreezePathGuard`）。ほかにもあれば足す
   - 「通すようにすると変わる場面」には、同じ経路の中で後から読まれる値（シークの保留・着地窓・位置の信頼）が消えて、その経路自身の処理が変わらないかを必ず書く
2. 経路ごとに赤いテストを 1 件以上書く（今のコードで失敗する。`[Fact(Skip = "v0.5.3 段 3b で直す（§6 の 2）")]` でコミットできる状態）。
   段 0 の表で「意図 = 消える」「現状 = 残る」の組を、経路ごとに確かめる形にする
3. 表の最後に所見を 5 行以内: 経路ごとに「通してよい」「通すと自分の処理が壊れる（別の直し方が要る）」「判断が要る」のどれか

## 規則

- **製品コードは変えない。git の書き込み禁止**（md とテストを足すだけ。コミットは親がする）
- 非 E2E を回して全件合格（Skip の新テストを除く）を確かめる
- 終わったら、表の行数・赤いテストの件数と Skip を外したときの失敗の内容・所見をこの画面に書く
