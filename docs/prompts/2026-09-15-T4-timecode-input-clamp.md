# T4: タイムライン オフセット入力の丸め込みと繰り上がり

利用者の指示（2026-09-15）:

> ffは動画素材のフレームによってはその範囲外の数値を入れてしまうこともできてしまう
> （例えば30fpsなのに 00:00:00;55 など）と思っていて、その場合に丸め込むような処理は
> 入っていますか？ フレームレートは事前に取得できるので、範囲を超える値を入れたら
> 強制的に最大のフレーム値に丸め込む形にしたいです。上の例なら、55が29になるような。

**v0.4 の範囲に入れる。**

---

## 1. 現状（親がコードで確認した事実）

`PlaylistTrackFormatter.TryParseTimecode`（`PlaylistTrackFormatter.cs:59`）:

```csharp
string[] parts = text.Split(':');
if (parts.Length != 4) return false;
...
if (frames < 0 || frames >= fps) return false;     // ← 範囲外は「編集そのものを拒否」
if (seconds < 0 || seconds >= 60) return false;
if (minutes < 0 || minutes >= 60) return false;
if (hours < 0 || hours > 99) return false;
```

**問題が 2 つある。**

### 問題 A: 丸め込みが無く、入力ごと拒否される

`00:00:00:55`（30fps）は `false` を返し、`PlaylistTimelineOffsetEditStatus.ParseFailed` になる。
**値が直らないうえ、なぜ拒否されたのかも操作者に伝わらない。**

### 問題 B: 区切り文字がコロンのみで、セミコロンを受け付けない

表示も `FormatTimecode` が `{hours:D2}:{minutes:D2}:{seconds:D2}:{frames:D2}` で、
セミコロンを使っていない。`Split(':')` が 4 要素を要求するため、
**`00:00:00;55` と入力すると 3 要素になって同じく拒否される。**

現場の慣習では **`;` はドロップフレームを表す**ので、入力として来る可能性がある。

### fps は取得できている

`PlaylistTimelineOffsetEditor.cs:47`:

```csharp
int fps = targetTrack.FrameRate.HasValue
    ? (int)Math.Round(targetTrack.FrameRate.Value)
    : (int)Math.Round(fallbackFps);
```

**素材のフレームレートを丸めた値**（29.97 なら 30）が使える。ご要望の丸め込みは実装可能。

## 2. 仕様

### ff は最大値へ丸める

`frames` が `fps` 以上なら **`fps - 1` へ丸める**。負なら 0 へ。

| 入力 | 素材 fps | 結果 |
| --- | ---: | --- |
| `00:00:00:55` | 30 | `00:00:00:29` |
| `00:00:00:30` | 30 | `00:00:00:29` |
| `00:00:00:24` | 24 | `00:00:00:23` |
| `00:00:00:-3` | 30 | `00:00:00:00` |

**拒否ではなく丸め。** 編集は成立させる。

### ss / mm は上の桁へ繰り上げる

`seconds >= 60` や `minutes >= 60` は**上の桁へ繰り上げる**（丸めない）。

| 入力 | 結果 |
| --- | --- |
| `00:00:75:00` | `00:01:15:00` |
| `00:75:00:00` | `01:15:00:00` |

現場では「75 秒」と入れたいことがあり、**拒否より繰り上がりの方が自然**（利用者の判断）。

繰り上げは **ff の丸め込みの後**に行う（丸めた ff は秒へ繰り上がらない。
`fps - 1` は定義上 1 秒未満のため）。

### hours の上限

`hours > 99` は現行どおり**拒否**でよい（繰り上げ先が無いため）。
繰り上がりの結果 100 時間を超える場合も拒否する。

### 区切り文字

**`:` と `;` の両方を受け付ける。** フレームの直前がどちらでも同じ値として解釈する。
`00:00:00;55` と `00:00:00:55` は同じ。

**表示（`FormatTimecode`）は現行のコロンのまま変えない。**
このアプリはドロップフレームの番号付けを扱わないため、`;` で表示すると誤解を招く。
入力だけ寛容にする。

### 操作者へのフィードバック

**丸めや繰り上がりが起きたら、UI の入力欄を確定後の値で書き戻すこと。**
`00:00:00:55` と入れたら `00:00:00:29` が表示される状態にする。
**黙って違う値を採用しない。** 現場で「入れたつもりの値と違う」が最も困る。

`PlaylistTimelineOffsetEditStatus` に丸めが起きたことを示す状態を足すか、
結果に確定値を含めて呼び出し側が書き戻す。設計は実装側が提案してよい。

## 3. 依頼

1. 単体テストを先に書く。最低限:
   - 上の表の丸め込み（30fps / 24fps / 60fps / 負値）
   - 繰り上がり（`00:00:75:00` → `00:01:15:00`、`00:75:00:00` → `01:15:00:00`）
   - `;` 区切りが `:` と同じ結果になる
   - **範囲内の入力が現行と完全に同一**（回帰しないこと）
   - 100 時間超は拒否
   - 丸め・繰り上がりが起きたことを呼び出し側が判別できる
2. 実装する
3. UI で確定値を書き戻す
4. 非E2E を全て通す

## 4. 守ること

1. **`FormatTimecode` の表示形式は変えない**（コロンのまま）
2. `LtcTimecode.ToRealSeconds`（同期経路）とは**別物**。こちらはタイムライン編集専用で、
   ドロップフレームも 29.97 の実時間換算も扱わない。**混ぜないこと**
3. 合否判定は書かないこと
4. `main` へ書き込まない
5. 実機は要らない
