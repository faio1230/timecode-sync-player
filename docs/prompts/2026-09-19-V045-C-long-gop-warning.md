# 0.4.5-C: ロング GOP の素材に警告を出す

**利用者の要望（2026-09-18）**: 「このような素材が来た場合、プレイリストやステータスバーなどどこかに
不安定になる可能性がある警告を出した方がいいかもしれません」

**0.4.5-A・B と独立。触る場所が重ならないので並行してよい。**

---

## 1. なぜ要るか

D37 で確定したこと: **補正シークが連鎖するかどうかを決めるのは「素材の重さ」ではなく GOP 長**。

- シーク 1 回の所要は**直前のキーフレームから目標まで復号する時間**。
  目標がキーフレームを越えるまで所要はほぼ比例して伸び、**越えた瞬間 184ms に落ちる**（実測）
- 4K60・10 秒 GOP ではシーク所要が 555ms〜2,038ms。許容（0.240 秒）を大きく超える
- **シーク所要が許容を超える素材では、シークは原理的に収束しない**（着地時の誤差 ≒ シーク所要）。
  そのため 0.4.4 は速度補正で詰めるが、**ずれ 1 秒あたり約 10 秒かかる**
- 同じ 4K60 でも **1 秒 GOP なら所要は 184ms 級**で、この問題自体が起きない

**つまり、素材を差し替えれば直る問題である。** 現場が本番前に気づけるようにする。

## 2. 何を出すか

**素材を読んだ後、なるべく早く**「この素材は同期が不安定になる可能性がある」と伝える。

- 出す場所: **ステータス行**（`MainWindow.xaml` の `SyncCorrectionStatusText` / `GpuStatusText` と同じ帯）
  **と、プレイリストの該当トラック行**。どちらか片方ではなく両方
  （ステータス行は「いま鳴っている」、プレイリスト行は「どのトラックが原因か」を示す）
- 文言は**対処が分かる形**にする。例:
  「キーフレーム間隔が長いため同期が不安定になることがあります（推奨: 1〜2 秒）」
- **エラーではない。再生は止めない。** 色や強調は控えめに（ライブ中に注意を奪わない）

## 3. どう判定するか

### 3-1. 見る場所: デコーダに入る符号化フレーム

キーフレームは `GST_BUFFER_FLAG_DELTA_UNIT` **が立っていない**バッファ。

- **デコード後のフレームではこのフラグが当てにならない**ので、
  **パーサ／デマルチプレクサ側の src pad にパッドプローブ**を付けて見ること
- shim 内で間隔を measure し、アプリへ報告する

### 3-2. 「2 つ目のキーフレームを待たない」

素直に「キーフレーム間隔を測る」と、10 秒 GOP では**判明まで最大 20 秒**かかる。そうではなく:

> **一定時間キーフレームが現れなかった時点で、その場で警告する。**

10 秒 GOP なら**再生開始から約 3 秒で出る**。キーフレームが来たら間隔を確定して、必要なら文言を更新する。

**しきい値: 3 秒**（現場推奨の 1〜2 秒 GOP を誤検出しない余裕を取った値）。
環境変数で上書きできるようにしてよい（既定 3 秒）。

### 3-3. 状態の持ち方

- **トラック単位**。トラックを切り替えたらリセットする
- 一度警告を出したトラックは、**同じセッション中は測り直さない**（点いたり消えたりさせない）
- 実際に測れた間隔（秒）を**ログとトレースに残す**（後から素材の一覧を作れるように）

## 4. 触らないもの

- 同期の制御則（許容・Jump・Smooth・速度補正の分岐）。**これは表示だけの変更**
- 再生の可否。警告が出ても再生は通常どおり続ける

## 5. テスト

- 単体: キーフレームが 3 秒現れなければ警告状態になる
- 単体: 1 秒間隔のキーフレームでは警告状態にならない
- 単体: トラック切替で状態がリセットされる
- 単体: 一度警告が出たトラックで、警告が消えたり点いたりしない
- 既存の非E2E がすべて通ること

## 6. 実機での確認

1. **10 秒 GOP の 4K60**（`artifacts/l1-vp9c/media/a_vp9_4k60_longgop85.mkv` と同仕様）で、
   **再生開始から何秒で警告が出るか**。狙いは 3〜4 秒
2. **1〜2 秒 GOP の素材**で警告が出ないこと（誤検出の確認）
3. 測れた間隔の値が実際の GOP と一致すること（`ffprobe` の値と突き合わせ）
4. 既存シナリオ 22 + LTC ループ 14（判定が変わらないこと）

## 7. 守ること

1. 合否判定は書かない。数字と証跡の場所だけ
2. 実機を使う前に親へ一報する
3. main への書き込みはしない
4. **表示だけの変更に留める。** 同期の挙動は変えない
