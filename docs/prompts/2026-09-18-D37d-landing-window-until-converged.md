# D37-d: 着地窓を「収束するまで」開いたままにする

**D37-c の穴 1 が再発した。機構は検証機が特定。親の最初の指示は誤りで、実測で訂正された。**

---

## 1. 検証機が特定した機構

**「直っていない」のではなく、「着地窓が 1 回目のシークの着地で閉じてしまう」問題。**

M3 の 2 つの run は「着地窓が開く → 1 回目のシーク（delta 3.5 秒）」まで**まったく同じ**。
**そのシークが 1.8〜2.0 秒かかり、着地した瞬間に同じだけの誤差が残る**（着地時の誤差 ≒ シーク所要）。

**次の判断のとき、もう着地窓の保護が切れており、通常の「誤差 vs 学習済みシーク所要」の比較に戻る。**

```
limitMs = 1,866.2（学習値）
残誤差 2,059ms > 1,866 → シーク → 3.77 秒で収束（9 回中 1 回）
残誤差 1,829ms < 1,866 → 速度補正 → 19 秒（9 回中 8 回）
```

**2 つの値がほぼ同じなので、わずかな差で分岐する。実質五分五分の賭け。**

**標準セット（M3 を 1 回）で合格していたのは、9 回に 1 回の側に当たったから。**

## 2. 親の最初の指示は誤りだった

親は「**着地窓の中なら誤差の大きさに関係なくシークに行く**」（上限 5 秒 / 連続 3 回）と指示した。

**エージェントがそのとおり実装し、L-1 ×3 で 3/3 失敗した。**
**誤差が小さくなった後もシークし続け、D37 の連鎖に戻るため**（シークが所要時間ぶんの誤差を作る）。

**机上ではなく実測で訂正された。指示どおり作って落としてから持ってきたのが正しい進め方。**

## 3. 採用した形

**着地窓の中では、誤差が「シーク所要見積り × 0.5」を超えるときだけシークを優先する。**

| 状況 | 判定 | 効果 |
| --- | --- | --- |
| 誤差 1,829ms、見積り 1,866ms | 1,829 > 933 → **シーク** | 19 秒の賭けを回避 |
| 誤差 200ms、見積り 1,866ms | 200 < 933 → 速度補正 | 連鎖を回避 |

**窓を閉じる条件**: 誤差が許容内に入ったとき。
**上限**: 窓が開いてから 5 秒、または連続シーク 3 回。どちらかで閉じて通常の判断に戻す。

**上限の理由**: 0.5× でもシークが縮まらない素材では連鎖しうる。**上限が最後の歯止め。**
5 秒は、事前登録した `waitedSeconds` の上限と同じ（超えたらもう合格しないので粘る意味がない）。

## 4. 0.5 は理論値ではなく調整値である

**必ず文書にそう明記すること。** 分かっている根拠は 2 点だけ。

- 検証機の帯（誤差 1,829ms vs 見積り 1,866ms）でシーク側に倒れる
- 小さい誤差（数百 ms）で速度補正側に落ち、連鎖に戻らない

**「なぜ 0.5 か」を説明できないなら、説明できないと書く。**
後から別の素材で破綻したとき、**調整値だと分かっていれば調整できる**が、
理論値だと思っていると原因を別の場所に探す。

### 置き換えの道筋（分かれば）

検証機の実測では 1 回目 1.99 秒 → **2 回目 0.97 秒**。
**学習値（1,866ms）は平均なので、2 回目の実際の所要はそれより短い**——これが 0.5× が効く理由と見ている。

**距離が短いからか、1 回目で近くのキーフレームまで復号済みだからか**が分かれば、
**0.5 という調整値を「その時点の目標距離から見積もる」に置き換えられる。**
