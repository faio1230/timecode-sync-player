## 依頼 A（最優先）: ばらつきの原因を計測で出す

**連続再生中（シークもギャップも無い区間）に、誤差が p5 -263ms から p95 -5.7ms まで揺れている。**
mpv は同じ区間で -143ms 〜 -36ms に収まる。**なぜ GStreamer だけ揺れるのかを、推測ではなく計測で出す。**

### やること

`TestResults` に残っている親の run を使ってよい（新規に測ってもよい）:

- `TestResults/a1v/a1-gst-gpu`（GStreamer×Gpu、COMPLETE）
- `TestResults/a1v/a1-mpv-gpu`（mpv×Gpu）

`analysis/accuracy-samples.csv` の `signedErrorMs` が大きく振れているサンプルを特定し、
**同じ時刻の出力トレース（`events.jsonl`）と突き合わせて、揺れが発生する段階を 1 つに絞る。**

候補となる段階（どこで時間が伸びているか）:

| 段階 | 見るイベント |
| --- | --- |
| デコード→配信 | `gst.delivery` の到着間隔、pts の刻み |
| 配信→取得 | `source.acquire` の `arrival->acquire age` |
| 取得→合成 | `compose.start` → `compose.complete` |
| 合成→公開 | `compose.publish` |
| 公開→走査 | `present.scanout` |

**出してほしい表**: 誤差が大きいサンプル（|誤差| > p90）と小さいサンプル（|誤差| < p10）で、
上の各段階の所要時間がどう違うか。**差が出る段階が 1 つに絞れれば、それが原因の場所。**

> **注意**: `compose.acquire` の `NotReady` は「このティックに新しいフレームが無い」という意味で、
> 欠落ではない。V1 で 25fps 58.3%、29.97fps 50.0%、59.94fps 0.2%、60fps 0% と
> ちょうど (60-fps)/60 に一致することを確認済み。**これを遅延の指標に使わないこと。**
