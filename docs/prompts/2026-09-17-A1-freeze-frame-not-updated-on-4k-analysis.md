## 2. 解析してほしいこと

1. ギャップ進入の 3 経路（D21-b の (a) 現在の絵を確定 / (b) `SeekToFinalFrame` / (c) `LoadPreviousTrackFinalFrame`、D22 の先頭オフセット）で、**一時停止中のシーク／ロード後にフレームが届く**までの経路（shim の pump、`TCS_PUMP_BUDGET_MS`、`compose.sourcePending`、D21 の「進入後に届いたフレームだけ確定」）を追い、フレームが **pump の予算内に届かない**（CPU デコードの 4K で 1 枚目が 161 ms、プロファイル試行 8 件で 1〜2.5 秒）ときに何が起きるかを書く。held が古い絵のまま確定される経路、または確定されずに前の held が残る経路があるか
2. F-1 の「終端 0.17 秒手前で保持」: ギャップ進入の契機（EOS / near-end 判定 / LTC がギャップに写像）と、その時点の表示フレームを確定する順序。60fps で 10 フレーム手前になる条件
3. 開発機で再現する案: `scripts/make-e2e-media.ps1` に **4K60 ProRes（`prores_ks`）と 4K24 AV1（`libaom-av1` か `libsvtav1`）の色素材**を追加して F-1/F-3/F-4/F-5 を回す（実素材不要）。CPU デコードの重さが再現の鍵と見ている。生成に必要なエンコーダが ffmpeg にあるかを確認し、無ければ代替（HEVC 4K60 10bit の CPU プロファイル強制 `TCS_FORCE_DECODER_ADAPTER_MISMATCH` など）を提案
