# v0.5.2 段 2g-1: 一時停止の持ち主の棚卸しと、§6 の 12 の赤いテスト（w5:p3 向け）

作業ツリー `timecode-sync-player-v05`、ブランチ `v0.5.2`（`cf74ca5` 以降）。**製品コードは変えない。**
背景は設計書 `docs/design/v0.5.2-sync-state.md` の §2 末尾（一時停止の持ち主が 5 つ）・§3「一時停止の持ち主の集合」・§6 の 12。
2f-1 の表 `docs/design/v0.5.2-cross-axis-rules.md` の #9〜#13・#26・#27 も読むこと。

## 目的

段 2g は v0.5.2 で**唯一振る舞いを変える**件（§6 の 12: 境界ホールドの解除 `SetEndHold(false)` が、ほかの持ち主が止めていても再生を再開する）。
**変わってよいのは 12 だけ**。一時停止の持ち主の集合を入れる前に、今の一時停止・再開の経路を全部洗い出し、
「集合が空のときだけ再開する」をどこに当てると何が変わるかを親が判断できる材料を作る。

## やること

1. `docs/design/v0.5.2-pause-owners.md`（新規）に、一時停止する経路と再開する経路をすべて表にする:

   | # | 持ち主（信号断 / 境界ホールド / ギャップ / プロジェクト復元 / 利用者 / その他） | 止める or 再開 | 場所（ファイル:メソッド） | 再開するとき、ほかの持ち主の何を見ているか（見ていなければ「なし」） | 集合が空のときだけ再開にすると変わる場面（無ければ「なし」） |

   - 「その他」があれば必ず書く（読み込み・停止・自動送りなど、一時停止の状態を直接書く経路）
   - 各持ち主の「自分が止めた」の記録の仕方（`_pausedByPolicy`、`_pauseOwnedByGap`、`ProjectRestorePauseState`、境界ホールドのラッチなど）も書く
   - 利用者の一時停止は今どこにも持ち主として記録されていないはず。その扱い（利用者が止めている間に他の持ち主の再開が来たら今どうなるか）を書く
2. §6 の 12 を再現する**赤いテスト**を書く（`tests/TimecodeSyncPlayer.Tests/` に新しいファイル。今のコードで**失敗する**ことを確かめる）:
   - 例: Single で境界ホールド中に信号断（停止モード）でも一時停止している → LTC が範囲内へ戻ってホールドが解除される → 今は再生が再開してしまう（期待: 再開しない）
   - 例: 境界ホールドとギャップの組み合わせが Single で起こりうるなら、それも（起こりえないなら理由を書く）
   - テストは `[Fact(Skip = "v0.5.2 段 2g-2 で直す（§6 の 12）")]` にして**コミットできる状態**で置く。Skip を外すと赤になることを報告に書く
3. 表の最後に、所見を 5 行以内で書く: 「集合が空のときだけ再開」を境界ホールドの解除だけに当てた場合と、全部の再開経路に当てた場合で、それぞれ何が変わるか

## 規則

- **製品コードは変えない。git の書き込み禁止**（md とテストを足すだけ。コミットは親がする）
- 非 E2E を回して全件合格（Skip の新テストを除く）を確かめる。E2E は回さなくてよい
- 終わったら、表の行数・赤いテストの件数と Skip を外したときの失敗の内容・所見をこの画面に書く
