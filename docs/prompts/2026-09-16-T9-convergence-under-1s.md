# T9: シーク・切替から 1 秒以内に ±80ms へ収束させる

**利用者の承認済み（2026-09-16）。** V3 の合格基準が「1 秒以内に ±80ms」に確定したため、現状（最大 1.27 秒）を縮める。

---

## 1. 現状の内訳（親が既存トレースから分解。推測ではない）

`t7b-77350e1`（Smooth、先行補償 off、LTC 25）の ±80ms までの収束: seek-a 1.02 / seek-b 1.17 / seek-c 1.27 / seek-back 1.07 秒（3〜4 本の最大）。

1 回の切替の時間の使い方（`scripts/analyze-v3-seek-breakdown.py` の出力より、中央値）:

| 区間 | 時間 |
| --- | ---: |
| 最初の LTC を受けて読み込みを出すまで | ほぼ 0 |
| **読み込み → 最初のフレームが出る**（`b→c`） | seek-a 92ms / seek-b 122ms / **seek-c（60fps）265ms** / seek-back 91ms |
| 最初のフレーム → 公開 | 2〜11ms |
| **残った 100ms 前後の残差を Smooth が詰める** | **約 0.7 秒** |

**支配的なのは最後の 0.7 秒。** Smooth は `rate = 1 + clamp(e / 1.0s, ±0.10)` なので、100ms の残差を詰めるのに 10% の余裕しか使えない。

補償（`SeekLatencyCompensator`、製品の既定は有効）を有効にして 3 本測った結果（親、2026-09-16 07:25）:

| | 平均 | p95-p5 | ±80ms への収束（seek-a / b / c / back の最大） |
| --- | ---: | ---: | --- |
| 補償 off | -25.7ms | 71.9ms | 1.02 / 1.17 / **1.27** / 1.07 秒 |
| 補償 on | -24.3ms | 81.7ms | 0.81 / 0.77 / **2.38** / 0.25 秒 |

**60fps クリップ（seek-c）だけ 2 倍以上悪化する。** 親の判断: **補償は既定で切る。**

## 2. 直すこと

### 2-1. 先行補償を既定で無効にする

- `SeekLatencyCompensator` の既定を無効にする。環境変数 `TCS_SEEK_LATENCY_COMPENSATION` は残し、**`on` を指定したときだけ有効**にする（測定用）
- 起動時のログで、有効・無効のどちらかを 1 行残す
- コードは消さない（除去は段 2・3 の整理でまとめて判断する）
- 既存テストの期待値を更新する

### 2-2. 着地直後だけ、Smooth の速度の上限を ±20% にする

**利用者の承認済み。** 定常状態は従来どおり ±10%。

- 「着地」= **トラック切替のロードが成立したフレーム**、および**粗い同期シーク（`SyncDecisionEngine` の Seek）を発行したフレーム**
- 着地から **1.0 秒**の間、`MaxRateDelta` を **0.20** にする。窓を過ぎたら 0.10 に戻す（その時点の倍率も 0.10 の範囲へ丸める）
- 窓の間に新しい着地があれば、そこから 1.0 秒に取り直す
- 窓は Smooth のときだけ効く。**Jump は変えない**（T8 の担当）
- 2 秒の「効かない」判定（`smooth-ineffective`）、デッドバンド 20ms、戻りバンド 10ms、時定数 1.0s は**変えない**
- 時刻は `Evaluate` に渡す `now` を使う（テストで進められるように）
- 上限を切り替えたことがログで分かるようにする（毎フレームは出さない。切り替わった時だけ）

### 2-3. 設定・文書

- `docs/SETUP.md` の Smooth の説明に、着地直後だけ ±20% になることと、その理由（収束を 1 秒以内にするため）、音のピッチが一時的に倍まで振れることを書く
- 上限・窓の長さは定数にし、根拠をコメントに書く（設定項目は増やさない）

## 3. テスト（非E2E）

- 着地の直後（窓の中）、残差 200ms で `rate = 1.20`、-200ms で `0.80`
- 同じ残差でも、窓を過ぎたら `1.10` / `0.90`
- 窓の中で残差 50ms なら `1.05`（比例のまま。上限だけが変わる）
- 窓の終了時に、掛かっていた倍率が 0.10 の範囲へ丸められる
- 窓の中に新しい着地が来たら、そこから 1.0 秒に延びる
- Jump は窓の有無で挙動が変わらない
- `SeekLatencyCompensator` の既定が無効で、`TCS_SEEK_LATENCY_COMPENSATION=on` でだけ有効になる
- 既存の Smooth・T7 のテストがすべて通る

## 4. 実機での確認

条件は T7b と同じ（gst / `outputBackend=1` / LTC 25 / Debug / 出力トレース有効）。**先行補償は環境変数を設定しない**（新しい既定 = 無効を測る）。

1. `scripts/run-v3-accuracy.ps1 -Backends gst -Label t9-<SHA> -Repeats 3`
2. 出すもの（合否は書かない）:
   - 定常誤差の平均・p50・p5・p95・p95-p5（run 別と 3 本結合）
   - **±80ms への収束時間（フェーズ別、3 本すべて）**。150ms・250ms の行も
   - 粗い同期シークの回数、`Smooth correction` の行数、上限を 0.20 に切り替えた回数
   - 着地時の残差（`analyze-v3-seek-breakdown.py` の `b→c` と、着地直後の `sync.evaluate` の delta）
3. 比較として `t7b-77350e1-ltc25-gst-1/3`、`t7b-parent-77350e1-ltc25-gst`（補償 off・±10%）を並べる
