# T3: 同期オフセット（全体に効く出力オフセット）

利用者の指示（2026-09-15）:

> UI付きでv0.4に入れるのはそうなんですが、その際は LTC のオフセットというよりは
> 全体にかけるオフセットの方がいい気がしています。
> なぜなら、LED までの出力を加味したオフセットを入れたいこともあるので。

**v0.4 の範囲に入れる。**

---

## 1. 何を補正するのか

信号の鎖は 1 本で、補正したい遅延は**両端**にある。

```
LTC 発生器 →ケーブル→ オーディオ IF → LTC デコード      [入力側 40〜90ms]
                                              ↓
                          同期判断 → デコード・合成 → HDMI / SDI 出力
                                              ↓
                              LED プロセッサ → LED ウォール   [出力側 1〜4 フレーム]
```

- **入力側**: LTC の値 T を知った時点で実時間は既に T+L。だから T+L を出すべき
- **出力側**: 表示装置が D 遅れるなら、D 早く送り出すべき

**どちらも「映像を先に進める」という同じ操作**で、`target = ltcSeconds + offset` の 1 本で両方吸収できる。
**分けない。**

## 2. 仕様

### 設定

- `AppSettings` に **`SyncOffsetMs`**（`double`、既定 **0**）を追加
- 範囲 **-1000 〜 +1000 ms**。範囲外は clamp して警告ログ
- **グローバル設定**（`settings.json`）。入力遅延はマシン固有、LED の遅延は会場固有で、
  どちらも「この設置」の性質であってショーの性質ではないため。
  プロジェクト単位が要るなら v0.5 以降で検討する

### 符号の規約（**間違えると逆効果なので必ずこの向きで**）

**プラスで映像が先に進む。** 下流の遅延を補償する方向。

| 状況 | 入れる値 |
| --- | --- |
| LTC が 80ms 遅れて届く | **+80** |
| LED ウォールが 2 フレーム（33ms）遅れて光る | **+33** |
| 両方 | **+113** |

UI には「**＋で映像が先行（下流の遅延を補正）**」と明記すること。

### 適用箇所

**LTC の値に対して、同期の入口で 1 回だけ足す。**

```
effectiveLtcSeconds = ltcSeconds + SyncOffsetMs / 1000.0
```

これにより、同期判断・シークのターゲット・クリップの切替タイミング・ギャップの出入りが
**すべて一貫してずれる**。個別に足して回らないこと（ずれの原因になる）。

`SyncMode.Single` と `Continue` の**両方**に効くこと。

### UI

- 現場で仕込み中に調整する前提なので **UI が要る**（`decodeMode` と違い settings.json のみにしない）
- **単位は ms。UI に「ms」を必ず表示すること**（利用者の指示、2026-09-15）。
  ラベルまたは入力欄の隣に出し、**何の単位か分からない数値入力にしない**
- **フレーム単位では出さない。換算の併記もしない。**
  このアプリは「**異なる fps のタイムコードと素材を実時間で吸収する**」のが設計思想であり、
  fps 依存の単位を操作系に持ち込むとその概念が濁る。
  LTC fps と素材 fps が違うとき「何フレーム」はどちらのフレームか曖昧になる。
  **実時間（ms）が唯一の単位**であることを UI でも一貫させる
- 変更は**即時反映**。再起動を要求しない
- `AutomationProperties.AutomationId` を付ける（E2E / UIA 用）

### 名前について

**「LTC オフセット」にしない。** 補正対象は入力側だけではないため。
`SyncOffsetMs` のように、**何をするかで名づける**（関連: 型名にランタイム名を入れない方針）。

## 3. 測定との関係（重要）

**V3 の測定は `SyncOffsetMs = 0`（既定）で行う。** オフセットを入れると測定値がその分そのまま動き、
映像側の実力が見えなくなる。**オフセットは現場の調整手段であって、精度を作る手段ではない。**

T2（LTC 入力遅延の直接測定）の結果は、**現場で入れるオフセットの初期値の目安**として使える。

## 4. 依頼

1. 単体テストを先に書く。最低限:
   - **設定値・保存・UI 表示のすべてが ms で一貫している**（内部だけ秒、UI だけフレーム等にしない）
   - 既定 0 で現行と完全に同一の挙動
   - `+100ms` でターゲットが 100ms 進む
   - 負の値でも対称に効く
   - 範囲外が clamp され警告ログが出る
   - Single と Continue の**両方**に効く
   - クリップ切替のタイミングもずれる（同期判断だけでなく）
2. 実装する
3. UI を足す（即時反映、AutomationId 付き）
4. `docs/SETUP.md` に設定項目と符号の規約を書く
5. 非E2E を全て通す

## 5. 守ること

1. 合否判定は書かないこと
2. 実機は親の合図を待つ
3. `main` へ書き込まない
4. デッドゾーン（`ToleranceFrames = 6.0`）は**変えない**
5. 疑問があれば実装前に聞くこと
