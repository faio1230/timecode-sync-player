# D37-a: 粗い同期シークを「瞬間値」で出さないようにする

**根本原因が確定したので直す。** 測定は済んでいる（下記）。**製品コードの変更を伴う。**

---

## 1. 確定した事実（検証機の実測、8 回 ×60 秒）

### 連鎖の起点は「測定値の振動」だった

最初の補正シークが出る直前 3 秒:

- `gst.delivery` は中央間隔 0.017 秒（60fps を維持）、0.1 秒超はせいぜい 1 回
- `compose.publish` は中央間隔 0.017 秒、0.1 秒超は 0 回
- LTC も正常（decodedFrames 50〜51／2 秒、frameDelayMedian 33.8〜40.8ms、警告なし）

**デコードも合成も詰まっていない。** 跳ねているのは**残差の測定値**:

```
-2.44s  rate=1.00541  residual=  +5.4ms
-1.53s  rate=1.00000  residual=  +0.3ms   ← ここまで 39 秒間ずっと安定（0.3〜5.4ms）
-0.41s  rate=1.01128  residual= +11.3ms
-0.36s  rate=1.03956  residual= +39.6ms
-0.31s  rate=1.00000  residual=  -1.0ms
-0.26s  rate=1.10000  residual=+118.4ms
-0.15s  rate=0.98858  residual= -11.4ms
-0.05s  decision action="Seek"  delta=0.253   ← 0.240 をわずかに超えて発火
```

**50ms の間に +118ms → −11ms は、実際の再生位置の動きでは起こりえない**
（rate 1.1 でも 50ms で動けるのは 5ms）。**測定値そのものが振れている。**

### 発火はすべて許容ぎりぎり

8 回の初回シークの発火値: **7 件中 6 件が 0.246〜0.285**（許容 0.240 のすぐ上）、残り 1 件が 2.738。
**振動の振幅（±100〜170ms）が許容 240ms に迫っているので、瞬間値だと当たってしまう。**

### いったん出ると自己維持する

シーク中は位置が止まり LTC だけ進むので、**着地時の誤差 ≒ シーク所要**（47 件で中央値 0.99）。
4K60 のシークは中央値 555ms・最長 2,038ms なので、着地した瞬間にまた許容超過 → 連鎖。

## 2. 直すこと

### 2-1. 粗い判定を瞬間値で出さない（本丸）

`SyncDecisionEngine.Decide` が 1 サンプルの `delta` で `Seek` を返している。これを次のどちらか（または両方）にする。

- **直近 N サンプルの中央値**が許容を超えたときに `Seek`
- **N 回連続**で許容を超えたときに `Seek`

N の決め方: LTC は 25fps で 40ms 間隔、観測された振動は 50ms ごとに符号が反転する。
**250ms 程度の窓（5 サンプル前後）**で中央値を取れば、この振動は消えるはず。
**遅れの代償**: 本物のずれに対する反応が最大 250ms 遅れる。シークの着地が 0.5〜2 秒かかることを思えば許容範囲。

**判定の入力だけを変え、許容値（6 フレーム）や目標の作り方は変えないこと。**

### 2-2. 物理的にありえない標本を弾く

残差の変化量には上限がある。50ms の間に位置が動ける量は最大でも `50ms × 1.20`（着地窓の上限レート）に
LTC の粒度（1/fps）を足した程度。**これを大きく超える変化をした標本は、測定の乱れとして扱う**
（捨てる、または中央値の材料に入れない）。

**捨てた標本は数えてログに出すこと**（どれくらい乱れているかを後から見たい）。

### 2-3. 影響範囲

- **Jump 補正（80ms のしきい値）と Smooth は触らない。** 今回の対象は粗い判定だけ
- 保持の明示着地（`ReapplyHeldValueOnPause`）も触らない
- 既存のシナリオ 22 本・LTC ループ 14 本の判定を変えないこと

## 3. テスト

- 単体: 振動する系列（実測の値をそのまま使ってよい: +11.3 / +39.6 / −1.0 / +118.4 / −11.4 / +253）で、
  **中央値・連続条件のどちらでもシークを出さない**こと
- 単体: 本物のずれ（一定して 0.3 秒を超え続ける系列）では、**N サンプル後にシークを出す**こと
- 単体: 2-2 の除外が効くこと（ありえない跳ねを含む系列で、除外の回数が数えられる）
- 既存の非E2E がすべて通ること

## 4. 実機での確認

1. **生成 4K60（キーフレーム 10 秒の重い素材）で L-1 を 3 回**。見るのは
   - 補正シークの回数（修正前は 6〜18 回、きれいな回は 0〜1 回）
   - 停止合計と最長（新しい判定: 単発 500ms、60 秒あたり合計 1.0 秒）
   - 最大誤差（修正前は 0.2〜3.8 秒）
2. **既存のシナリオ 22 本 + LTC ループ 14 本**（判定が変わっていないこと）
3. V3 を 1 本（同期精度が落ちていないこと。平均・p95-p5・収束）

## 5. 守ること

1. 変えるのは粗い判定の入力だけ。**許容値・目標・Jump・Smooth・保持の着地は触らない**
2. 合否判定は書かない。数字と証跡の場所だけ報告する
3. 実機を使う前に親へ一報する
4. main への書き込みはしない

## 6. これで直らない部分（別の課題）

- **シーク中に絵が止まること自体**は変わらない。本物のずれでシークが出れば、4K60 では 0.5〜2 秒止まる
  → 「重い素材ではシークを出さず速度補正に任せる」（D37-b）で別途扱う
- **測定値が振れること自体**も残る。これは 0.4.5 の設計改善（速度の推定、時刻付けの改善）の対象
  → 振幅が ±100〜170ms もある理由（1080p/25fps では ±20〜40ms だった）は、
  4K60 で UI スレッドが逼迫していることと関係している可能性がある（調査中）
