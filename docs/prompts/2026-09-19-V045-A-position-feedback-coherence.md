# 0.4.5-A: 再生位置のフィードバックを一貫させる

**0.4.4（D37-a / D37-b2）が「暴れる入力を避ける」で対処した部分を、「正しい入力を作る」に置き換える。**
根拠はすべて実測と、`docs/analysis/2026-09-18-LTC-sync-0.4.5-regrade.md` のコード読み。

**0.4.4 を統合してから着手すること。** 0.4.4 が main に入る前に始めない。

---

## 1. 何が問題か

`tcs_player_get_time_pos`（`native/gst-shim/src/tcs_gstreamer.cpp:3411-3452`）は、
**1 つの API で 2 つの異なる時計**を返している。

| 状態 | 返す値 | 実装 |
| --- | --- | --- |
| 一時停止中（pump 完了、`latest_gen == generation`、PTS>0） | 最新配信フレームの stream-time PTS | 3425-3429 |
| それ以外（**再生中は常にこちら**） | `gst_element_query_position`（パイプライン／セグメント位置） | 3430 |
| クエリ失敗時（再生中も） | **世代チェック無しで**最新配信 PTS | 3434-3437 |

シークはすべて flushing で、`seek_prepare_locked` は再生中もパイプラインを PLAYING のままにする。
このため**シーク中は「旧位置」と「新目標 + 経過時間」の間で値が跳ぶ**。

**実測**: 連鎖中の再生位置の残差 σ **445ms**（最小 −781 / 最大 +567ms）。同じ区間で LTC 側は σ **0.36ms**。
**振動の出どころは位置の問い合わせだと確定している。**

一方、**表示済みフレームの PTS は shim 内に既にある**（`latest_pts_ns`、`tcs_gstreamer.cpp:1452-1453`。
trace の `gst.position.ptsNs` / `gst.delivery`）。使っているのは一時停止経路だけ。

## 2. 先に 1 回だけ確認すること（実装前）

**コード読みに基づく推定なので、実測で裏を取ってから実装に入ること。**

`gst.position` イベントにはクエリ値と最新配信 PTS が**同時に**残っている。x1 の既存トレース
（`TestResults/x1-d37b/` など、シークが出ている run）で次を切り分ける。

- シーク発行から着地までの各サンプルで、**返った値がどちらの時計だったか**
  （クエリ値 ≒ 目標＋経過 なのか、旧位置なのか、配信 PTS と一致するのか）
- **クエリ失敗（3434 のフォールバック）が実際に起きているか、何回か**

**推定と違っていたら、実装に入る前に報告すること。**設計を見直す。

## 3. 作るもの

### 3-1. shim: 返す値に「基準」と「世代」を付ける

`get_time_pos` の呼び出し側が、**返ってきた位置が何を指しているか**を判別できるようにする。

- 基準: `pipeline`（`query_position` の値） / `delivered`（配信フレームの PTS）
- **世代**（`generation`）: その値がどのシーク世代のものか
- 配信 PTS を返す経路は、**3434 のフォールバックも含めて世代チェックを通すこと**（現状は素通し）

既存 API を壊さないこと。**追加の関数か、出力引数の追加**で行う。どちらにしたかを報告に書く。

### 3-2. アプリ: 着地が未確認の間は「配信 PTS 基準」で誤差を評価する

- 着地が確認できるまで（`GstSeekingTracker.cs:64-88` の判定）、**誤差の評価を止めるのではなく、
  配信 PTS を基準にして評価を続ける**
- 配信 PTS は離散なので、**「最後の配信 PTS + 経過時間 × 実測レート」で外挿**する。
  外挿の上限は LTC 側と同じ考え方で **0.5 秒**（`LtcAnchorFilter` に前例がある）
- **絵が止まっていれば位置も止まる**（外挿は経過時間ぶんだけなので、配信が来なければ頭打ちになる）。
  これが狙いで、「目標への跳び」に汚染されない誤差が得られる

### 3-3. D37-b2 の抑制を置き換える

3-2 が入れば、**「着地が確認できるまで判定しない」は不要になる**（正しい入力で評価を続けられるため）。

- **ただし外すのは、3-2 が実機で機能することを確認してから。** 先に 3-2 を入れて両方が並ぶ状態で測り、
  抑制を外した状態でも同等以上であることを示してから外す
- **D37-b2 の「ギャップ明け・切替の着地はシーク、定常の不足は速度補正」は残す。**
  これは入力の質とは別の、手段の選択の話

## 4. 触らないもの

- 許容値（6 フレーム）、Jump のしきい値（80ms）、Smooth の制御則
- LTC 側（アンカー、時刻付け）。**σ 0.3ms で安定しており、直す対象ではない**
- 表示フレームの選択（リング複数枚など。案 3 は実施しない）

## 5. テスト

- 単体: 基準と世代が付いて返ること。古い世代の配信 PTS は採用されないこと
- 単体: 着地未確認の間、配信 PTS + 外挿で誤差が評価されること
- 単体: 配信が止まったとき、外挿が 0.5 秒で頭打ちになること
- 既存の非E2E がすべて通ること

## 6. 実機での確認

1. **シークが出る run で、位置側の残差 σ を測る。** 目標は **445ms から大幅に下げる**こと
   （LTC 側の 0.36ms には届かなくてよい。フレーム量子化ぶんは残る）
2. **L-1 ×3**（VP9 4K60）— 0.4.4 の水準（シーク 0 回、停止 0 秒、最大誤差 0.1 秒前後）を維持
3. **V3 を 1 本** — 定常・収束・black-sweep の回復が 0.4.4 と同水準
4. 既存シナリオ 22 + LTC ループ 14
