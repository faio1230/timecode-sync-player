# L-1: 実素材で 60 秒の連続追従を回し、途中で詰まらないかを集計する

**利用者の依頼（2026-09-18）**: 「1 分ほど LTC を実素材に引っ掛けて、途中で詰まらないかを集計するテスト」。
**素材を何本使うかは検証機が決める**ので、テスト側は本数と長さを外から変えられるようにする。

---

## 1. なぜ要るか（いまの穴）

現行のシナリオで、LTC を連続で当て続ける最長区間は **S-1 の 10 秒**しかない。

| いまあるもの | 長さ | 中身 |
| --- | --- | --- |
| S-1 | 10 秒 | 追従中の `frameUpdates` を 2 秒ごとに見る（1 トラック内） |
| G-5 / F-4 | 約 50 秒 | 2 秒ごとに保持と切替を繰り返す（連続追従ではない） |
| R-1〜R-4 | 10〜20 秒 | 停止・ランスルーの保持と再開 |
| V6 | 60 分 | **LTC 同期なし**の連続再生（生成素材） |

**現場の使い方（LTC を流しっぱなしで長く回す）に一番近い区間が、いちばん薄い。**
候補 5・候補 6 で見つかっている間欠（0x0 ロード、メタデータ待ち、保持の取りこぼし）も、
長く回したときに出る種類のもの。

## 2. 作るもの

`LtcScenarioE2ETests` に **L-1** を足す。Single モードで、**1 トラック内を連続追従**する。
切替もギャップも保持も入れない。「詰まるか」だけを見る。

### 手順

1. アクティブにするトラックを選ぶ（既定は A）
2. そのトラックの範囲内から始めて、**LTC を連続送出**（既定 60 秒。素材が短ければ後述の丸め）
3. 送出中は **2 秒窓**で次を記録する
   - `frameUpdates`（アプリログの `Playback perf`。S-1 と同じ読み方）
   - 位置の進み（窓の終わり − 窓の始め）
   - LTC の写像と位置の誤差（窓内の最大）
4. 終わったら集計して journal に書き、判定する

### 判定（すべて満たす）

| # | 条件 |
| --- | --- |
| 1 | **更新が 0 の窓が 0 件**（`frameUpdates == 0`） |
| 2 | **位置が進まない窓が 0 件**（進み < 窓長 × 0.5） |
| 3 | 各窓の最大誤差が **±0.3 秒**以内（既存の `PositionToleranceSeconds`） |
| 4 | ERR ログ 0、残プロセス 0（既存の共通判定） |

### 集計して報告に出すもの（journal と要約）

- 窓の数、詰まった窓の数（条件 1・2 に触れた窓）、**最悪の窓**（`frameUpdates` 最小、進み最小、誤差最大とその時刻）
- 全体の平均 `frameUpdates` と、素材の fps から見た期待値
- 使った素材（記号）、トラックの尺、実際に回した秒数

## 3. 外から変えられるようにするもの（**検証機が決める**）

環境変数で受ける（製品の設定は増やさない）。既定値は開発機で回せる値にする。

| 変数 | 既定 | 意味 |
| --- | --- | --- |
| `TCS_L1_FOLLOW_SECONDS` | 60 | 連続追従の秒数 |
| `TCS_L1_TRACKS` | `A` | 対象トラック（`A,B,C` のように複数可）。複数なら 1 本ずつ順に回す |
| `TCS_L1_WINDOW_SECONDS` | 2 | 集計する窓の長さ |

- **素材が短いとき**: そのトラックの使用尺（`used`）から余裕（先頭 2 秒・末尾 2 秒）を引いた長さに丸める。
  丸めた結果が **30 秒未満なら Skip**（理由に素材の記号と尺を書く）。丸めたときは実測秒数を報告に出す
- `run-ltc-scenarios.ps1` から渡せるようにする（`-FollowSeconds` / `-FollowTracks` など。名前は任せる）。
  **既存の 22 本の挙動と所要時間は変えないこと**（L-1 は追加。既定フィルタに含めるかは下記）

### 既定フィルタの扱い

- 既定の実行（`run-ltc-scenarios.ps1` をそのまま回す）には **L-1 を含める**（1 本 60 秒 + 前後で約 1.5 分の増）
- ただし `-Filter` で従来 22 本だけを回せるようにしておく

## 4. 検証（実機は親の合図を待つ）

1. 非E2E（新規の単体があれば足す。窓の集計ロジックは純関数にして単体で固定できるとよい）
2. 実機で L-1 を 1 本（生成素材、既定 60 秒）
3. 実機で L-1 を `TCS_L1_TRACKS=A,B,C` の 3 本（生成素材）
4. 既存 22 本が変わらず通ること（1 回）

報告には、2・3 の集計（窓の数、詰まった窓、最悪の窓、平均 `frameUpdates`）と trx のカウンタ、証跡の場所を入れる。
**合否は書かない**（親が出す）。

## 5. 守ること

1. 製品コードは変更しない。テストとランナーだけ
2. 既存 22 本の判定・所要時間・出力形式を変えない
3. 実機を使う前に親へ一報する
4. main への書き込みはしない。`agent-a` にコミットする
5. 公開文書に素材名やローカルパスを書かない（記号 M1〜M7 / A〜C で書く）
