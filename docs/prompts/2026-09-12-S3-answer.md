# S3 の質問への回答（親、2026-09-12 19:45 JST）

原因の特定（TS に IDR ごとの SPS/PPS が無く `tsdemux` の `scan_keyframe_h264` が NAL を見失う）は妥当。
提示された 1〜4 はいずれも採らない。理由と、採る方向（5）を示す。

## 1〜4 を採らない理由

- **1（tsdemux を修正・更新した DLL を配布）**: LGPL の改変バイナリの配布と、上流更新のたびのパッチ保守を
  ライブ用途の製品に抱えるのは割に合わない。最後の手段として残すが今は採らない。
- **2（素材を正規化）**: **一般化しない。親が独立に確認した**。
  `ffmpeg -i v1_h264_1080p5994.mp4 -c copy -bsf:v "h264_mp4toannexb,dump_extra=freq=keyframe" -f mpegts`
  で作った `artifacts/media/v1/short/v1_h264_ts_dumpextra.ts` は、ファイルサイズが元の remux より
  +2820 バイト（≈ 60 IDR × SPS+PPS）で**ヘッダは実際に入っている**が、`tcs-shim-test` は同じ 2 件が失敗し、
  `scan_keyframe_h264: Error identifying nalu` が 20 回残る（正規化前は同種の警告が 87 回）。
  そもそも現場に持ち込まれる素材は選べない。**利用者の方針は「mpv から GStreamer へ完全移行」**なので、
  「その素材は mpv で再生する」という退避も取れない。
- **3（待ち延長・再シーク）**: 体感の停止 2〜4 秒が残るので不可。LTC 同期では毎回のシークでこれが出る。
- **4（KEY_UNIT 単独）**: 着地 target−2.4 秒は不可。同意見。

## 採る方向（5: shim 側で正確なシークを自前で組む）

`tsdemux` の ACCURATE 走査に頼らず、**キーフレームへ飛んでから目標まで捨てる**。

1. シークは `GST_SEEK_FLAG_FLUSH | GST_SEEK_FLAG_KEY_UNIT | GST_SEEK_FLAG_SNAP_BEFORE` で
   目標以前の最寄りキーフレームへ飛ぶ。
2. その後 **pts < target のフレームは共有リングへ配信せず捨て**、pts ≥ target の最初のフレームから配信する
   （デコードは進める。捨てる間も世代は上げ直さない＝**世代の上げは 1 シークにつき 1 回**）。
3. 捨てている間、合成側は Held を描いたままにする（**I7: 黒を出さない**）。C# と C ABI は変更しない。
4. 適用範囲は **まず MPEG-TS（`tsdemux`）のみ**。MP4／MOV は現行の ACCURATE が着地誤差 1ms 台で問題ないので変えない。
   全コンテナで統一したい根拠が計測で出たら提案すること（実装側で決めない）。
5. `gst_element_seek` の戻り値を見て、偽なら `last_error` に記録する（現状は見ていない）。

## 報告に必須の計測

- **着地誤差**（`post-seek lease pts` − target）: MP4 と同等（1 フレーム未満）であること。TS と MP4 の両方を出す。
- **シーク発行 → 新世代フレーム到達までの時間**: TS と MP4 の両方。**目標 500ms 以下**（`step` の 500ms 予算も満たす）。
- **GOP が長い素材での挙動**: 1 秒 GOP 以外を 1 本作って測る（例 `x264enc key-int-max` で 5 秒 GOP の TS）。
  捨てるフレーム数と到達時間を出す。
- 捨てたフレーム数、およびその間に黒フレームが出ていないこと。

## 合格条件（更新）

- `tcs-shim-test` が **failures=0**: `v1_h264_1080p60.ts`、`short\v1_h264_ffmpegmux.ts`、
  `short\v1_h264_ts_dumpextra.ts` の 3 本。`lease pts near seek target` も満たすこと。
- 回帰: v1 の 11 素材すべて failures=0。非E2E 全件成功。
- 実機 1 本: TS を 50 秒、GStreamer×Gpu。実フレーム 60/秒、合成 p99 1ms 前後、error 0、exit 0。
- 1 コミット（shim＋README）。基点は main `ef70564`。

## 到達時間が 500ms を切れない場合

方式を変える前に、**計測値を添えて再度質問すること**。その数字を見て 1（tsdemux 側の修正）の採否を親が判断し直す。
