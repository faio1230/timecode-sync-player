# 0.4.5-B: 定常遅延を測って `SyncOffsetMs` の推奨値を出す

**小さい作業。制御則は変えない。** 0.4.5-A と並行してよい（触る場所が重ならない）。

---

## 1. 根拠

制御ループが見ている「報告位置」と、現場が実際に見ている「表示済みの絵」は別物である。
M3 の実測で、差は **固定 −27〜−29ms + 変動 σ 11〜12ms**（p95 の絶対値で 40〜46ms）。

**固定ぶんは消せる。** これは現場の見え方に直結する。

**ループには入れない。** 表示 PTS をフィードバックにすると復号・合成・表示の遅延ぶんの位相遅れが
制御に入り、変動は 25fps の 1 フレーム（40ms）と同程度でフレーム量子化と区別できない。
**測って推奨値を出すだけ**にする。

## 2. やること

1. **固定遅延を素材条件ごとに測る**
   - 少なくとも **fps（24 / 25 / 29.97 / 30 / 60）** で分ける。解像度・コーデックでも変わるなら分ける
   - 変わらないなら「変わらない」と報告する（そのほうが推奨値が 1 つで済む）
2. **推奨値の出し方を決めて、文書に書く**
   - 固定遅延の**中央値**を使う（平均ではない。外れ値に引かれるため）
   - 変動 σ が固定ぶんと同程度以上なら「推奨値を出す意味が無い」と報告する
3. **`SyncOffsetMs` の既定値を変えるかどうかは提案だけ。** 変更は親が決める

## 3. 測り方

- 既存の V3 ハーネス（`scripts/run-v3-accuracy.ps1`）と M3 の集計をそのまま使ってよい
- **定常区間のみ**（settling と black-sweep を除く）。これは既存の集計と同じ扱い
- 素材条件ごとに **n と信頼区間**を必ず出す。n が小さい条件は「足りない」と書く

## 4. 報告に入れるもの

- 素材条件 × 固定遅延（中央値・p5・p95・n）の表
- 条件による差があるか、あるなら何で説明できるか
- 推奨値（1 つで済むのか、条件ごとに要るのか）
- 証跡の場所

## 5. 守ること

1. **制御則・ループの入力を変えない。** 測定と提案だけ
2. 合否判定は書かない
3. 実機を使う前に親へ一報する
4. main への書き込みはしない
