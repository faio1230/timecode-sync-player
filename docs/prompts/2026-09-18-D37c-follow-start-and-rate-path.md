# D37-c: 追従開始はシークで着地する／速度補正にも同じゲートを通す

**0.4.4 候補の検証機の結果で見つかった 2 つの穴を塞ぐ。どちらも親の設計の穴であって、実装の誤りではない。**

---

## 1. 検証機の実測（0.4.4 候補 `8703f4f`、実素材）

### 達成できていること

| | 0.4.3 | 0.4.4 候補 |
| --- | --- | --- |
| 補正シーク（M3） | 0〜18 回 | **0 回** |
| 停止合計（最大） | 10.90 秒 | **0.295 秒**（M4 の 1 回のみ） |
| シナリオ 3 通し | | 36 合格 / 0 失敗 ×3 |
| L-1 5 本 | | 4 合格 / **1 失敗（M3）** |

**D37 の狙い（シークの連鎖を止める）は実素材でも達成している。** ここは変えない。

### 穴 1: 追従開始までの待ちが M3 で 7.02 秒 → **18.05 秒** に悪化

他の素材は 0.52〜1.31 秒（開発機の生成素材は 1.84〜1.99 秒）。**M3 だけ 18 秒**。

**原因**: 追従開始時の大きなずれ（1 秒弱）を**速度補正で詰めている**。97ms/秒なので約 10 秒かかる。
未学習時の既定しきい値が 1.0 秒なので、**0.5〜1.0 秒のずれがすべて速度補正に回る**が、
M3 の実測シーク所要は 0.5 秒台であり、**シークの方が 20 倍速い**。

**設計の穴**: D37-b2 で「ギャップ明け・トラック切替の着地はシークで詰める」と決めた。
理由は「**その瞬間は画面が黒かフリーズなので、シークによる静止が見えない**」こと。
**追従開始の瞬間も同じ性質を持つのに、入れ忘れていた。**

### 穴 2: 振動が速度補正の経路に残っている（振幅はむしろ増大）

検証機の観測（M3、追従 42.1 秒の内訳）:

- **Seek decision gate の棄却 67 回**（新ゲートが不安定サンプルを弾き、シークを 0 回に抑えている。**狙いどおり**）
- rate catch-up preferred 12 回
- **Smooth correction 232 回。残差の絶対値は中央 60ms・最大 754ms・300ms 超が 34 回**
- **rate が 1.10 と 0.95 の間を 50ms ごとに振れ続ける**

**0.4.3 の振幅は ±100〜170ms、0.4.4 候補は ±300〜754ms。大きくなっている。**

**設計の穴**: D37-a の指示書に「**Jump 補正と Smooth は触らない。今回の対象は粗い判定だけ**」と
明記した。**同じ汚れた入力が速度補正に入り続けることを考えていなかった。**
ゲートはシーク経路だけを守っており、速度補正は生の値を使っている。

## 2. 直すこと

### 2-1. 追従開始の着地をシークで行う

- **追従を開始する瞬間**（同期の有効化、最初の LTC 追従開始）を、
  D37-b2 の着地窓（`NotifyLanding` / `RateCatchUpAllowed=false`）と**同じ扱い**にする
- つまり**追従開始直後の不足は、速度補正ではなくシークで詰める**
- 既存の「ギャップ明け・切替の着地」の経路に追従開始を足すだけでよいはず。**新しい機構を作らないこと**

### 2-2. 速度補正の入力にも、粗い判定と同じ前処理を通す

D37-a のゲートが持っている 2 つの前処理を、**速度補正の残差にも適用する**。

1. **物理的にありえない標本の除外**（LTC 40ms の間に位置が動ける上限を超える変化）
2. **直近 N サンプルの中央値**（瞬間値で反応しない）

**注意して分けること**:

- **除外（1）は無条件に入れてよい。** ありえない値は誰にとっても誤りである
- **中央値（2）は反応を鈍らせる。** Smooth の応答が遅れると収束時間（V3 の「1 秒以内に ±80ms」）に効く。
  **収束が悪化しないことを V3 で必ず確認すること。** 悪化するなら窓を短くする（3 サンプル等）か、
  除外（1）だけにする
- **Jump のしきい値（80ms）と Smooth の制御則そのものは変えない。** 変えるのは**入力の作り方**だけ

### 2-3. 触らないもの

- 許容値（6 フレーム）、Jump のしきい値、Smooth の制御則、D37-a のゲート本体、
  D37-b 2-2 の速度補正方針、D37-b2 の着地窓（2-1 は**そこに追従開始を足すだけ**）
- shim（今回もアプリ側だけ）

## 3. テスト

- 単体: 追従開始直後の不足はシークで着地する（定常の同じ不足は速度補正のまま）
- 単体: ありえない跳ねを含む系列で、速度補正の残差から除外される（除外回数が数えられる）
- 単体: 振動する系列で、速度補正の rate が上下限に張り付かない
- 既存の非E2E がすべて通ること

## 4. 実機での確認

1. **L-1 ×3（VP9 4K60 ロング GOP）**: シーク 0 回・停止 0 秒を維持したうえで、
   **追従開始までの待ちが 2 秒前後に収まること**
2. **V3 を 1 本**: **収束（シーク・切替から 1 秒以内に ±80ms）が悪化していないこと**。
   定常の平均・p95−p5 も非回帰であること。**2-2 の中央値の副作用はここに出る**
3. **残差の振れ幅**（Smooth の残差の中央値・p95・最大、rate が上下限に張り付いた回数）。
   検証機の M3 では 中央 60ms・最大 754ms・300ms 超 34 回だった
4. 既存シナリオ 22 + LTC ループ 14

## 5. 守ること

1. 合否判定は書かない。数字と証跡の場所だけ
2. 実機を使う前に親へ一報する
3. main への書き込みはしない
4. **変更点は最小限に。** 2-1 は既存経路に追従開始を足すだけ、2-2 は入力の前処理だけ

## 6. これで直らないもの（0.4.5-A の領域）

**振動の源は位置クエリそのもの**（シーク中は目標で凍結し、着地で溜まった誤差が一度に現れる）。
D37-c は**汚れた入力をフィルタする対症療法**であり、根治は 0.4.5-A（位置フィードバックの一貫化）。
**D37-c で振動が完全には消えなくてよい。** 速度補正が上下限に張り付かなくなれば目的を達する。
