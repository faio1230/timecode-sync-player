## 2. 判断の根拠

**「絵を止めない」ことに価値があるのは、定常の追従中だけ。**

- **定常中**: 画面には内容が映っている。シークすると 0.5〜2 秒静止し、静止した時間ぶん誤差が増えて連鎖する
  → **速度補正が正しい**（D37-b のとおり）
- **ギャップ明け・トラック切替の着地**: その瞬間は画面が黒またはフリーズしている。
  **シークによる静止は見えない**。一方で速度補正に回すと、**内容が 0.4〜0.7 秒ずれたまま数秒流れる**
  → **シークが正しい**（D37-a までの挙動）

同じ「不足」でも、**その瞬間に絵が出ているかどうか**で最適な手段が反転する。

## 3. 直すこと

1. **ギャップからの復帰（黒・フリーズの両方）と、トラック切替の着地では、従来どおりシークで着地させる**
   - 速度補正優先の対象を、**定常の追従中に生じた不足**だけに限定する
   - ギャップ出口・切替の着地は既存の経路（`ContinueOnTrackCoordinator`、`GapFreezeHandler` の状態）で識別する
2. **D37-b の他の挙動は変えない**（シーク中は位置を信用しない、定常の不足は速度補正で詰める）

## 4. テスト

- 単体: ギャップ明けの不足はシークで着地する
- 単体: 定常中の同じ大きさの不足は速度補正で詰める（シークを出さない）
- 既存の非E2E がすべて通ること
