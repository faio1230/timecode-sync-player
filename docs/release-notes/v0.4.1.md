# TimecodeSyncPlayer v0.4.1

v0.4.0 は 44.1kHz の音声付き素材が再生できない欠陥がありました。この版で修正します。あわせて、映像トラックが先頭の音声付き MP4 のロード停止、不一致プロファイルの待ち時間、同梱 GStreamer ランタイムの不足 DLL を修正し、shim のログをファイルへ残せるようにしました。

### 修正

- 44.1kHz 音声付き素材がロードできなかった。音声分岐に `audioresample` を入れ、端末のレートへ変換する（D12）
- 映像トラックが先頭の音声付き MP4 で preroll が止まっていた。映像分岐の demux 直後に `queue` を入れた（D13）
- 不一致のデコードプロファイルがタイムアウトまで待っていた。bus のエラーで即座に次の試行へ進む（D14）
- 同梱の GStreamer ランタイムに `gstaudioresample.dll` / `gsttypefindfunctions.dll` / `gio-2.0-0.dll` が無く、44.1kHz 素材と拡張子で判定できない素材が失敗していた（D15）

### 追加

- `TCS_LOG_FILE`: shim のログを `logs\tcs-gst-YYYYMMDD.log` へ出力する（7 日で清掃）
- 44.1kHz 音声と映像トラック先頭の素材を E2E に追加

## 検証の概要

- 開発機: 修正前に 44.1kHz 素材が全プロファイル失敗し、48kHz・音声先頭・1080p60 が成功することを確認
- 開発機: 修正後に 4 素材すべてが最初の一致プロファイルでロード（171.1 / 177.4 / 172.7 / 177.3 ms）
- 開発機: 44.1kHz 素材のループバック RMS は再生区間で平均 -21.1 dBFS（peak -18.1 dBFS）
- 開発機: V5 シーク連打は着地 10/10 目標値ちょうど、`compose.publish` の最長無公開 47.5ms、ERR 0
- 開発機: V3（Smooth、LTC 25）は sample 平均 -25.3ms、p95-p5 39.5ms
- 開発機: E2E 一部（GStreamerBackend / SystemScenario）は 6 合格 / 1 スキップ / 0 失敗
- 検証機: AV1 実素材 3 本 + 複製 2 本のロード・再生（親が記入）
- 検証機: 配布物の起動確認（44.1kHz 素材を含む）（親が記入）

## 動作要件

- Windows 10/11 x64、D3D11.4（共有フェンス）に対応した GPU
- インストーラーは GStreamer 1.28.2 ランタイムの一部を同梱し、Microsoft Visual C++ 2015-2022 再頒布可能パッケージを連鎖してインストールする
