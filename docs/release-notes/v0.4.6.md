# TimecodeSyncPlayer v0.4.6（下書き）

**不具合の修正だけの版です。** 同期の動き方の方針は変えていません。

外部のコードレビューで見つかった不具合と、その修正を検証機で確かめる途中で見つかった不具合（最後の 1 件）を直しました。どれも素材の良し悪しに関係なく、推奨どおりの素材でも起きうるものです。とくに 1 つめは v0.1.0 から残っていたもので、素材をプロジェクトとは別の場所に置く使い方をしていると、保存したプロジェクトを開き直したときにトラックが消えていました。

> 下書きの状態です。検証機での確認が済んでから確定します。

### 修正

- **素材がプロジェクトのフォルダーの外にあると、プロジェクトを開き直したときにそのトラックが消えていた。** 別のフォルダーや別のドライブにある素材も読めるようにした。以前は、素材がプロジェクトのフォルダーの外にあると、絶対パスで書かれていても読み込みを拒否し、ログに警告を 1 行残すだけでトラックを外していた（v0.1.0 から）
- **読み込めなかったトラックを、一覧で知らせるようにした。** 素材が見つからないときなどに、どのトラックをなぜ読み込めなかったかを表示する。そのまま上書き保存するとそれらのトラックがプロジェクトから外れることも、あわせて伝える
- **まれに GPU の処理が止まり、映像が出なくなることがあった。** v0.4.5 で入れた修正（D38）は、このうち一部の経路しか塞げていなかった。原因は、表示を待っているフレームを、その回の合成に使っていないのに「GPU で使用中」として扱い、後片付けの対象にも入れていたこと。同じフレームを二か所で持つ形になっていた。使っていないフレームは使用中にも後片付けの対象にもしないようにして、二重に持つ形そのものを無くした
- **同期のずれの測定値が一瞬跳ねたとき、その直後にシークが出ることがあった。** v0.4.5 で入れた「測定値の一瞬の揺れでシークしない」ための守りに抜け道があった。跳ねた値を捨てて測り直すときに、それまでの「ずれが続いた回数」だけが残っていたため、測り直した最初の 1 回で「続けてずれている」と判定されていた
- **再生速度の変更が受け付けられなかったとき、その値が内部に残っていた。** 次のシークでその速度が使われ、アプリが把握している速度と実際の速度が食い違うことがあった。受け付けられたときだけ値を書き換えるようにした
- **読み込み直後の一時停止中に、受け付けられなかったシークを成功として扱っていた。** アプリは起きていないシークの着地を待ち、再生側も止まったままの状態で動き出そうとしていた。受け付けられなかったシークは失敗として返すようにした（検証機のログでは、読み込みの途中だけで 7 回。追従中・再生中には一度も起きていない）
- **GPU が一時的に使えなくなったあと（デバイス消失からの復旧）に、映像の更新が戻らないことがあった。** 復旧のためにプレイヤーを作り直すとき、フレームが届いたことを知らせる仕組みの登録が消えていた。描画側も作り直す前のプレイヤーを参照したままになっていた。どちらも新しいプレイヤーへつなぎ直すようにした
- **タイムコードがクリップの範囲を越えたあと範囲内へ戻すと、0.65 秒ほどずれた位置に着地することがあった。** 追従開始のときだけ使う「シークにかかる時間ぶん先を狙う」補正が、戻したときのシークにも乗っていた。v0.4.5 では、この補正を終わらせるきっかけが「クリップの端での一時停止が解けたとき」だけだった。端へのシークに時間がかかって、端で止まる前にタイムコードが戻ると、補正が残っていた（検証機では端へのシークに 0.655 秒かかった）。タイムコードが飛んだ時点でも終わらせるようにした。経路は以前からあり、上の「測定値が一瞬跳ねたとき」の修正でシークの出るタイミングが変わったことで表に出た

### 変更

- README の動作要件に、必須の **Direct3D 11.4 に対応した GPU** を書き足した。ダウンロードとインストールの説明が v0.2.0 のファイル名のままだったので直した
- 設定リファレンスに、抜けていた設定（`syncOffsetMs`・`syncCorrectionMode`・`decodeMode`・`outputBackend`）と、環境変数の一覧を足した
- 現場準備ガイドの「ばらつきはゼロ」「解析中も再生に影響しません」などの言い切りを、測った条件に絞った書き方にした
