# TimecodeSyncPlayer v0.4.2

v0.4.0 / v0.4.1 は、内蔵 GPU と dGPU を積むノート PC で AV1 などの再生がクラッシュする欠陥がありました。この版で修正します。あわせて、コーデックが一致しないプロファイルごとに生じていた待ち時間を除去し、ロード時間を短縮しました。

### 修正

- ハイブリッド GPU で、リング（合成）と別アダプタの d3d11 デコーダが AMD ドライバ内でクラッシュしていた。shim アダプタにデコーダ GUID が無い GPU プロファイルは skip して CPU プロファイルへ（D16、v0.4.0 から存在）
- デコーダ要素をリングと同じアダプタのクラス（`d3d11…device{N}dec`）から選ぶようにした（D16-b）
- 一致しないプロファイルごとに 3 秒待っていた。caps 不一致を検出したら即座に次の試行へ進む。AV1 4K のロードは 18.8 秒 → 約 1 秒（D17）

### 変更

- 別アダプタのデコーダメモリを受け取った場合は、クラッシュせずロード失敗として記録する（`on_new_sample` の防御）

## 検証の概要

- 検証機（ハイブリッド GPU、クリーン環境）: AV1 6 本 + ProRes でクラッシュ 0、ロード 0.97〜2.2 秒（ProRes 1.17 秒）、`frameUpdates` 48〜49 / 2 秒
- 開発機: V5 シーク連打 10/10、V3 は sample 平均 -30.9ms・p95-p5 42.0ms、E2E 一部（GStreamerBackend / SystemScenario）6 合格 / 0 失敗、非E2E 1674 件
- 検証機: LTC 同期 E2E（VB-CABLE のループ、`LtcHardwareLoopE2ETests`）14 件合格 / 0 失敗。同期シーク 14 回すべて success、LTC デコード 25fps

## 動作要件

- Windows 10/11 x64、D3D11.4（共有フェンス）に対応した GPU
- インストーラーは GStreamer 1.28.2 ランタイムの一部を同梱し、Microsoft Visual C++ 2015-2022 再頒布可能パッケージを連鎖してインストールする
