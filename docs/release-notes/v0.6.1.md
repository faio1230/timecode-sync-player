# TimecodeSyncPlayer v0.6.1

**安定版（Latest）です。**
LTC の信号が乱れた直後に、位置の合わせ直しが続けて出て映像が止まる件を直しました。v0.6.0 の ProRes の GPU 復号と、v0.5.6 の修正を含みます。

v0.5.6 からの移行の注意: 無し（設定・プロジェクトの形式は変わりません。新しい設定 `proResGpu` が無ければ「自動」）。v0.5.x から上げる場合は、v0.6.0 の変更（下の「v0.6.0 からの内容」）もあわせて確かめてください。

### 修正

- **LTC の信号が乱れた直後に、位置を合わせ直すシークが続けて出て、重い素材（4K や 60p。H.264 でも ProRes でも）で最大 0.6 秒ほど映像が止まることがあった。** v0.5.4 から。
  化けた値の次に届いた正しい値を、新しい位置への Jump と取り違えて受け直していた。値の判断を、直前の 1 枚とではなく、受理済みのタイムコードの流れと比べて行うようにした。検証機で同じ型の乱れが起きた回は、受け直しの確定 0 回・位置合わせのシーク 1 本で、映像の止まりは基準（0.5 秒）の内側だった（v0.5.6 では確定 4 回・シーク 3 本・0.555 秒）
- **LTC が止まらずに 1 フレームずつ「這う」ように進むとき（送出がゆっくりになる場合）も、止まったと扱う。** 停止モードは止めたまま、新しい値へ 1 回ずつ着地する。ランスルーは合わせ直さない
- **ランスルーで LTC が止まっている間、保持値への 1 回の合わせが毎フレーム繰り返され、後ろ向きのシークが何本も出ることがあった。** 名前どおり 1 回にした
- v0.5.6 の修正（プレイリストにファイルを足した直後に選んだ行が、読み取りの完了で再生中の行へ戻る）を含みます

### 振る舞いの変化

- **ランスルーで LTC が止まった（または進まなくなった）間、映像は走り続け、LTC が戻ったときに 1 回だけ位置を合わせ直します。** v0.5.x では止まっている間に小さな合わせ直しが繰り返され、映像が細かく止まっていました。長く止まった後ほど、戻るときの巻き戻しは大きくなります（3 秒なら約 2.6 秒）。LTC を頭の 1 秒ほどだけ当てて位置を取り、その後は LTC 無しで走らせる使い方もできます
- LTC が止まった位置から再開したとき、信号断からの復帰が 1 フレーム（約 33〜40ms）遅れます（止まった位置からの再開の 1 枚目は、復帰の数に入れない）
- 停止モードで LTC が止まった後、化けた値だけが届き続けるときは、停止の理由が「タイムコード停止で停止中」のままになります（v0.6.0 では約 0.3 秒後に「信号断で停止中」に変わっていた）。どちらも止まったままです
- ログに、層 2 の分類の件数の行（`LTC layer2 summary`）を、監視の停止とアプリの終了のときに 1 行出します（診断用）

### v0.6.0 からの内容（v0.5.x から上げる場合）

- **ProRes の GPU 復号**（gst-prores-d3d11 v0.2.1 を同梱）。既定（自動）では NVIDIA の GPU でだけ使い、ほかの GPU では CPU で復号します。画面の「ProRes の GPU 復号: 自動 / 有効 / 無効」で切り替えます（再起動の後に反映）。NVIDIA の機では、ProRes の素材が既定で GPU で復号されます（v0.5.x は常に CPU）
- インストーラーは Microsoft Visual C++ 再頒布パッケージ 14.50.35710 以上を求めます。古いときだけ同梱の 14.51 を入れ、そのときはインストールの途中で一度だけ管理者の確認（UAC）が出ます
- 開発・試験のスクリプトは PowerShell 7 が要ります（利用者が使う `inspect-gop.ps1` は Windows PowerShell 5.1 でも動きます）

### 既知の不具合

- 推奨素材の範囲内で既知の不具合は 0 件です（v0.6.0 の 3 件は、v0.6.1・v0.5.6 で直したか、下の「既知の間欠」へ移しました）

### 既知の制限

- **ProRes の GPU 復号は NVIDIA（RTX 級）で検証しました。** AMD・Intel の GPU は既定（自動）では CPU で復号します。設定で「有効」にできますが、サポート対象外です
- GPU の復号で、壊れたフレームの検出が最大 3 フレーム遅れることがあります（プラグインの制限）
- メモリ（システムのコミット）が尽きた環境では、復号のメモリの確保に失敗してアプリが終了することがあります（GStreamer の性質）。空き 4 GB 以上を目安にしてください
- VC++ 再頒布パッケージが 14.50 より古い PC では、インストールの途中で一度だけ管理者の確認（UAC）が出ます。無人でインストールするときは、先に VC++ 再頒布パッケージ（14.50 以上）を入れておいてください
- キーフレームの間隔が長い素材（推奨の 1〜2 秒を超えるもの）では、追従が止まって飛ぶことがあります。推奨の範囲外です（SETUP の「素材の推奨」）
- ProRes は「推奨」の素材ではなく「可」のままです

### 運用の推奨

- **本番では LTC の fps を固定（25 / 29.97 / 30 など、LTC の発生器と同じ値）に設定してください。** 「自動」は、つないだ LTC の fps が分からないときに確かめるための補助の設定です（SETUP の「LTC fps モード」）

### 既知の間欠（まれに起きる）

- 終了時の資源の解放に約 15 秒かかることがある（v0.5.4 の開発機の試験で、アプリの終了 1,652 回中 1 回）。そのまま正常に終了する
- 起動の直後、画面の操作に約 1 秒反応しない区間がある（初期化の間）。その後は反応する
- インストールした直後の最初の起動で、数秒反応しないことがある（検証機で 1 回）。2 回目以降は起きない
- 速度の補正を位置の合わせ直しの直後に送ると、GStreamer がログに `gst_segment_do_seek: assertion` の CRITICAL を出すことがある（診断の行だけ。速度は指示どおりに変わることを確かめた）
- LTC の大きな Jump の直後に後ろ向きの位置合わせが起きた後、映像が約 1.5 秒黒になったことが v0.5.5 の検証機で 1 回あった。v0.6.0 の候補 2・v0.6.1 の候補の同じ試験（計 5 回以上）と、同じ列の再生 200 回以上では起きていない。同じトラック内の位置合わせでは、新しい絵が届くまで直前の絵を出し続け、黒を描かない（コードで確認）。当時のアプリのログに、黒を描く経路（ギャップの黒・GPU の復旧・試験用の設定）の記録は無く、黒の区間もアプリは新しいフレームを描いていた（確認済み）。試験の画面の記録に別の窓が重なった疑いがある
- （試験の側）UI の自動操作が起動の直後に時間切れになることがある。製品の動作ではない
