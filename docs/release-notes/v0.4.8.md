# TimecodeSyncPlayer v0.4.8

**映像の復号が一時的に追いつかなくなったとき、同期が揺れ続けないようにした版です。**

外部のツールが UI Automation で画面の表示を高頻度（50ms ごと）に読み続ける試験で、
同期の補正が 0.9 倍と 1.1 倍を往復し、性能の記録が 10〜20 秒途切れる現象が出ていました。
調べた結果、起点は UI の読み取りではなく**映像の復号が一時的に追いつかなくなること**で、
そのときの再生位置の揺れを補正がそのまま追いかけて、揺れを大きくしていました。

### 変更

- **再生位置が一時的に前後に揺れても、同期の補正が振り回されないようにした。** 復号が追いつかなくなると、
  再生位置の問い合わせが 100〜300ms 離れた 2 つの値を交互に返すことがある。これまではその値で
  再生速度を上げ下げしていた。今後は、同じ再生区間（シーク・読み込み・一時停止をしていない間）では
  位置を後戻りさせず、戻った直後の 1 秒は速度の補正を止めて等速に保つ。止めたこと・再開したことはログに残る
- **測定の乱れを弾いた直後の値を、そのまま採用しないようにした。** これまでは乱れを 1 つ弾くたびに
  それまでの記録を捨てていたため、正しい値と乱れた値が交互に来ると、乱れた値が 1 つおきに採用されていた
- **性能の記録（`Playback perf`）が途切れないようにした。** 位置が揺れて戻るたびに 2 秒の集計を
  やり直していたため、揺れが続くと記録が出なくなっていた。シーク・読み込み・一時停止の後は従来どおり
  集計をやり直す
- **同じ絵を出し続けたときの理由をログに残すようにした。** 100ms 以上同じ絵が続いた 2 秒の区間ごとに、
  復号側の完了待ちだったのか、新しい絵が届いていなかったのかを `Output held:` の行で出す
- 終了時、映像出力の停止が確認できないうちは、再生部品を破棄しないようにした（安全のため）
- 現場準備ガイドに、**4K60 の素材をどの GPU で動かすか**を書き足した（下の既知の制限を参照）

UI Automation の読み取りそのものは、表示の文字列を返すだけで再生には影響しないことを確かめた。

## 検証の概要

- **開発機**（2026-09-23、`ba43a11`、Debug）
  - 非E2E **2113 件合格 / 0 失敗**。E2E は一式で 84 件合格（当初の失敗 2 件は、実素材の要る試験を
    色素材で回したことと、UI Automation の一時的な例外。前者は実素材のときだけ回すよう直し、後者は単独で合格）
  - UI Automation で表示を読み続けても、再生位置の問い合わせ・シーク・同期の判断が増えないこと、
    映像の合成・受け取りが続くことを E2E で確認
- **検証機**（2026-09-23、候補 `6381e5e` と `ba43a11`、実素材 M1/M4/M7 を連続で 1650 秒、
  タイムコード 30fps、ギャップ無し、Spout 出力と外部の受信監査あり）
  - ノート PC で、**GPU を 2 通り**で回した（外付けの RTX 3080 と、CPU 内蔵の GPU）
  - **RTX 3080**: 表示の読み取り 50ms で 3 本とも合格、250ms で 3 本中 2 本合格、
    タイムコード 25fps・24fps で合格。不合格の 1 本は、PC 全体が約 1 秒止まった回
    （タイムコードの音声・映像の復号・Spout の受信・画面の読み取りが同時に遅れた。原因は未特定）で、
    同期はその後 1 回の追い付きで戻っている
  - **内蔵 GPU**: 修正前の v0.4.7 では性能の記録が 10.7 秒途切れ、位置の停止が 5 回あった。
    この版では 3 本とも記録の途切れは 0。ただし**復号が追いつかないことによる映像の停止（250ms 以上）は
    16〜37 回残り**、復号の遅れが 12 秒続いた 1 本では位置の停止も 6 回あった。
    このとき GPU の復号の使用率は 75〜80% に張り付いていた。**同期の修正では直せない、機材の余裕の問題**
  - 修正前の v0.4.7 も、RTX 3080 では表示の読み取り 50ms で合格した

## 既知の制限

- **CPU 内蔵の GPU では、4K60 の素材を実時間で復号しきれないことがある。** そのあいだ同じ絵が
  0.3〜0.8 秒出続け、長く続くと同期も一時的にずれる。4K60 の素材は、**外付けの GPU（例: RTX）で
  動かしてください。** アプリは「全画面の出力先に選んだディスプレイがつながっている GPU」を使う。
  出力先を選ばない（Spout だけで使う）ときは Windows の既定の GPU を使い、ノート PC では内蔵の GPU に
  なることが多い。その場合は Windows の「グラフィックスの設定」でアプリを「高パフォーマンス」にする
  （Spout の受け手のソフトも同じ GPU にそろえる。Spout は GPU をまたいで共有できない）
- PC 全体が一時的に止まると（検証機で 1 回、約 1 秒）、その間は映像も同期も遅れる。アプリ側では防げない
- ほかは v0.4.7 と同じ
