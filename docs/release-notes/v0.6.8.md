# ERYTHEIA v0.6.8

**試験版（Pre-release）です。本番には安定版 v0.6.6（Latest）を使ってください。**
この版では、高性能の GPU があるのに内蔵 GPU で動いているときに、操作画面に警告を出すようにしました。あわせて、いま使っている GPU の名前を操作画面に出します。同期の規則・ゲート・定数と、同期と LTC のコードは v0.6.7 と同じです。設定とプロジェクトの形式も v0.6.7 と同じです。ほかの内容・既知の制限・運用の推奨は v0.6.7 と同じです（[v0.6.7 のリリースノート](https://github.com/faio1230/timecode-sync-player/releases/tag/v0.6.7)）。

### 足したもの

- 起動のとき、内蔵 GPU で動いていて、ほかに高性能の GPU があれば、右の欄の「出力」の欄に警告を出します。文は次のとおりです
  - 「⚠ 内蔵 GPU で動いています。Windows の「設定 → ディスプレイ → グラフィック」で ERYTHEIA.exe を「高パフォーマンス」にして、再起動してください。」
  - GPU の復旧で内蔵 GPU に移ったときは「⚠ GPU の復旧で内蔵 GPU に移りました。区切りのよいところで再起動してください。」
  - 警告の文にマウスを乗せると、いま使っている GPU と高性能の GPU の名前、「4K60 の素材はカクつくことがあります」、もう一つの直し方（全画面の出力先の見直し、または画面をつなぐ端子）が出ます
- 警告は操作を止めません。確認の窓は出さず、全画面の出力と Spout の絵には載せません
- 警告の右の「×」で、その起動の間だけ消せます。次の起動でまた判定し、当たればまた出します。GPU の復旧の後に判定し直して内蔵 GPU なら、消していてもまた出します
- 判定には、Windows が分けた GPU の並び（高性能の順と省電力の順）を使います。メーカーの名前では判定しません。リモート デスクトップの中、ソフトウェアの描画で動いているとき、再生が無効のときは判定しません
- 「出力」の見出しの行の右に、いま使っている GPU の名前を「GPU: 名前」の形で出します。警告が見えている間は隠します。GPU の復旧の後は、移った先の名前に変えます
- 起動のときと GPU の復旧の後に、ログへ `GPU placement: at=… used=… origin=… highPerformance=… minimumPower=… verdict=… reason=…` の行を 1 行ずつ出します（Information）。警告を出したときは `GPU placement warning shown:` の行を出します（Warning）

### 既知の制限

- **「省電力」を指定していると警告は出ません。見出しの右の GPU の名前を見てください。** Windows の「グラフィック」の設定で ERYTHEIA.exe を「省電力」にすると、高性能の順と省電力の順の先頭がどちらも内蔵 GPU になり、内蔵 GPU で動いていても警告が出ません
- **ノート PC で外付けの画面が内蔵 GPU の側につながる構成では、全画面の表示が周期的に約 30 fps に落ちることがあります。** 高性能の GPU で合成し、内蔵 GPU の側につながった画面へ全画面で出すと、画面への出力が約 20 分の巡りのうち約 7 分、約 30 fps になりました（4K の外付けの画面で 2 回のうち 2 回）。合成は 60 fps のままです。1080p の画面では測っていません。v0.4.0 からの作り（全画面の表示の時刻の予測）によるもので、次の版で直す予定です。この版の警告に従って「高パフォーマンス」を指定すると、この構成に入る機体があります
- 独立の GPU が 2 つある PC では、Windows の 2 つの並びの順によっては、省電力の順の先頭の GPU で動いているときに警告が出ることがあります（手元にこの構成の機体は無く、確かめていません）
- 「デコードの遅れ」の警告の数え方は v0.6.7 と同じで、この版では変えていません
- ほかは v0.6.7 と同じです

### 既知の間欠（まれに起きる）

- v0.6.7 のノートの一覧と同じです

### 検証の概要

- **開発機**（2026-11-16〜18、GPU は RTX 級が 1 つ）
  - 非E2E: 3,419 件合格、0 失敗、2 スキップ
  - E2E の一式（LTC のシナリオを除く）: 103 件のうち合格 84・失敗 3・スキップ 16。失敗の 3 件は v0.6.7 の候補の回でも同じく落ちた試験です
  - 一式の中の起動 60 回のうち、試験のための切り替えを使わない起動で、警告は 0 回でした（GPU が 1 つの機体では出ないのが正しい動き）。警告の表示・「×」・GPU の復旧の後の出し直しは、その切り替えで確かめました
  - 起動の所要: 判定の入る区間は前の版と比べて中央で約 6 ms 長く、回ごとの揺れの中でした
  - 4K の画面への全画面（6 分）: 全区間で約 60 fps でした
- **検証機**（2026-11-16〜17、内蔵の AMD の GPU と RTX 級の GPU を積むノート PC）
  - GPU の指定なし: 内蔵 GPU で動き、警告が出ました。「×」で消え、見出しの右に名前が出ました
  - 「省電力」: 内蔵 GPU で動き、警告は出ませんでした（上の既知の制限）
  - 「高パフォーマンス」: RTX で動き、警告は出ませんでした
  - 新しい GPU の E2E 3 件: 3 件とも合格
  - 標準のシナリオの回 1 本（RTX）: 合格 38・落ち 0・無効 1（既知のギャップ）。数のうち 2 つ（保留の入りの数と、3 つの数の和）が、前もって決めた範囲の下に外れました。説明はまだ付いていません
  - E2E の 2 クラス: 落ちは 1 件で、同梱の GStreamer に Matroska と AVI の demux が無いため（v0.6.7 と同じ既知の制限）
  - 4K の外付けの画面への全画面（RTX で合成、画面は内蔵 GPU の側）: 上の既知の制限の約 30 fps が 2 回とも出ました
- 試験版（Pre-release）のままにした理由: 標準のシナリオの数が 2 つ、前もって決めた範囲の下に外れ、説明が付いていないためです。v0.6.7 との違いに同期と LTC のコードは無く、落ちは 0 でした。範囲の作り直しと、静かな状態での標準のシナリオは、次の版の検証で回します
