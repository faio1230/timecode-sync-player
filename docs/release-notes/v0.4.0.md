# TimecodeSyncPlayer v0.4.0 (beta)

この版では mpv バックエンドと CPU 合成を除去しました。再生は GStreamer のみ、出力は GPU 合成のみになり、アプリの境界は型付きの再生 API になりました。

### 追加

- 型付きの再生 API（`IPlaybackApi` / `PlaybackResult` / `IRenderUpdateSource`）を追加し、文字列コマンドとプロパティ名をアプリの境界から排除した
- GStreamer による再生と GPU 合成出力を既定にした。デコード済みテクスチャを D3D11 の共有リングで受け取り、合成・全画面表示・Spout 送信まで GPU 上で完結する
- CPU デコードのコーデック（ProRes ほか）も `d3d11upload` で同じリース経路に載せた
- 音声トラック付き素材の再生（S1）
- MPEG-TS のシークをキーフレーム着地と segment の再基準化で正確にした（S3）
- LTC の fps モード（Auto / Fixed 24・25・29.97・30）と同期オフセット（`syncOffsetMs`、-1000〜+1000ms）
- 同期補正モード（Smooth / Jump）。着地直後 1 秒は Smooth の上限を ±20% に広げて収束を早める（T9）
- サンプル時計（`TCS_LTC_SAMPLE_CLOCK`、既定 on）。LTC の時刻を音声サンプル位置から評価する（T2）
- 共有リングの世代（ring epoch）を追跡し、解像度変更に追従して開き直す（D8）

### 変更

- mpv を除去した。再生は GStreamer のみになり、`backend` 設定は無くなった。退避は `decodeMode`（`hardware` / `software`）で行う
- CPU 合成を除去した。出力は GPU 合成のみで、`outputBackend` の既定は `1`（Gpu）。`0`（Cpu）は警告を出して無視し、設定ファイルは書き換えない
- ランタイム名を含む型名を役割名へ整理した（旧 `IMpvApi` ほか）
- V3（LTC 同期精度）の正式な解析を sample 解析（フレーム終端基準）にした
- パイプラインクロックをシステムクロックに固定し、音声シンクはそれにスレーブする（S3 の副作用）
- 終了手順の段名からランタイム名を外した（「GStreamer 停止」）
- Single モードでもクリップの `MediaOut` を再生の終端として扱う（Continue と同じ）

### 削除

- mpv バックエンドと `libmpv-2.dll` / `mpv-2.dll` の同梱
- `backend` 設定キーと `outputBackend=Cpu`（v0.3 の値は起動時に警告を出して無視）
- デバッグ OSD（`showDebugOsd` の OSD 表示。設定キーは互換のため残置）
- 旧 mpv 互換アダプタと文字列コマンド経路（`GstMpvApiAdapter` / `GstCommandTranslator` / `MpvPlaybackCommandBuilder` ほか）

### 修正

- 音声トラック付き MP4 が読み込めなかった（S1）
- ProRes ほか CPU デコードのコーデックが読み込めなかった（S2）
- MPEG-TS でシーク後にフレームが数秒届かなかった（S3）
- 解像度が変わるトラック切替で GPU 復旧後に再生が進まなかった（D8）
- B フレームありの MP4 で accurate シーク後に位置が実際より進んで報告されていた。shim がバッファの PTS ではなく segment 写像の stream time を使う（D10）
- ギャップ動作の切替時に、古い LTC フレームの再適用が同期要求を出していた（U1）
- E2E `ProjectRoundTrip` の失敗（テスト側のプレイリスト選択待ち。Q1）
- Single モードで EOF へシークした後 seeking が解除されず、LTC を戻しても同期シークが出なかった（D11）
- 一時停止中の位置つきロード直後に位置表示（ラベル・シークバー）が更新されなかった（F1）

### 既知の制限

- 29.97 ノンドロップの LTC は fps モード「Fixed 29.97」の指定が必要（Auto は 30 と区別できない）
- 本物の GPU デバイス消失（TDR）からの shim 復旧はこの版では未対応（D9）
- フレーム 1 枚分の定数は製品では足さない。現場の遅延は同期オフセット（`syncOffsetMs`）で合わせる
- 120Hz の出力先は未検証。4K 主画面を出力先にすると 40 秒あたり数フレーム落ちることがある（専用ディスプレイを推奨）
- トラック切替時に稀に 100ms 以下の音切れ（60 分試験で 12 回中 4 回）
- HAP は未対応

## 検証の概要

- V1 コーデック一覧、V2 音声、V3 LTC 同期精度（sample 基準、LTC 4 種）、V4 ギャップ動作（代替プロジェクト）、V5 トラック切替とシーク連打、V6 60 分連続、V9 起動・終了・復旧、V10 旧プロジェクトの読み込み
- E2E 全件: 63 件合格、0 件失敗（opt-in の 6 件はスキップ）
- 詳細: `docs/release-0.4-plan.md` と `docs/GSTREAMER-GPU-VALIDATION-PLAN-2026-09-12.md`

## 動作要件

- Windows 10/11 x64、D3D11.4（共有フェンス）に対応した GPU
- インストーラーは GStreamer 1.28.2 ランタイムの一部を同梱し、Microsoft Visual C++ 2015-2022 再頒布可能パッケージを連鎖してインストールする
