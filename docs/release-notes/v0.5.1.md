# TimecodeSyncPlayer v0.5.1

**LTC の入力が一瞬乱れても映像が飛ばないようにし、v0.5.0 で入った Single モードの不具合を直した版です。**
あわせて、同期の内部の整理を 2 件入れました（振る舞いは変わりません）。

### 修正

- **Single で、LTC がクリップの入口より手前にあるままトラックを切り替えると、新しいトラックが LTC を無視して
  頭から流れていた（v0.5.0 で入った不具合）。** 入口へシークしてホールドした記録を、次のファイルを読み込んだ後も
  使っていたため、新しいトラックの位置 0 を「入口に着いた」とみなしていた。いまは新しいトラックもまず入口へ
  シークしてからホールドする（クリップの出口側で止まっている場合は、以前から正しく動いていた）
- **LTC が一瞬化けたとき、同じトラックの中で映像が飛んでいた（以前の版から）。** LTC には誤りを見分ける仕組みが
  無く、ケーブルやミキサー側の乱れで化けた 1 フレームが「ジャンプ」に見えることがある。これまでは同じトラック内の
  ジャンプを最初の 1 フレームでそのまま採っていたため、2 時間の試験で化けた 1 フレームから +2.3 秒シークし、
  0.8 秒後に戻していた。いまはギャップや別トラックへのジャンプと同じく、次のフレームが続くのを確かめてから採る
  - 本物のジャンプ（LTC を送り側で飛ばしたとき）は 1 フレーム（30fps で 33ms）遅れて反応する
  - タイムコードが止まった状態からの再開は、これまでどおり最初の 1 フレームで反応する

### 追加

- **画面のプレビューが 1 秒以上更新されないとき、ログに記録する**（`Preview stalled:` / `Preview resumed:`）。
  下の「既知の制限」のプレビューの件を調べるためのもので、振る舞いは変えない

### 整理（振る舞いは変わらない）

- 同期に使う再生位置の読み取りを、1 回の照会で位置と時刻をまとめて返す形にした（これまでは 2 つの呼び出しを
  決まった順で呼ぶ必要があった）
- ギャップのフリーズ画像を確定する処理を、待たない非同期のメソッドから、ふつうの状態の切り替えにした

### 見送ったもの

- **トラック切替の直後の遅れを、読み込みにかかる時間ぶん先回りして詰める機能は入れなかった。** 推奨素材（H.264）
  では切替直後の遅れが 0.05〜0.07 秒で、これまでの追い付きで 0.15 秒ほどで収まる。遅れが大きいのは ProRes と
  キーフレーム間隔の長い素材だけで、前者は別にハードウェアデコーダーを開発中、後者は書き出し直すべき素材のため、
  同期の中心に仕組みを足さないことにした

## 検証の概要

- **開発機**（2026-09-24、Debug）: 非E2E **2110 件合格 / 0 失敗**
- **検証機**（2026-09-24、RTX 3080、実素材 M1〜M7）
  - **合否の一式（候補 5 `f238f32`）**: 標準のシナリオ 3 通りはそれぞれ 37 件合格・失敗 0。連続追従 6 本はすべて合格で、
    最大誤差 0.068〜0.084 秒（v0.5.0 は 0.062〜0.078 秒）、補正のシーク 0 回。エラー 0
  - **切替の多い周回（候補 4 `6e4afc4`、60 分、トラック入り 140 回・ギャップ入り 19 回）**: 時間切れ 0。
    切替直後のずれ 中央 0.034 秒（v0.5.0 は 0.050 秒）、落ち着くまで 中央 268ms（v0.5.0 は 264ms）。
    候補 5 との差は Single の修正だけなので、この結果を使った
  - **2 時間の連続再生（v0.5.0 で実施、課題の洗い出し）**: 定常の誤差 中央 0.024 秒・99% で 0.059 秒、
    Spout の外部受信 43 万フレームで 0.5 秒以上の途切れ 0、応答なし・エラー 0。
    出た課題（化けた LTC での飛び、プレビューの件）はこの版で扱った
  - **参考**: 利用者が本番で使った HAP 素材 5 本を RTX と CPU 内蔵の GPU で読み込み、10 回すべて GPU で再生できた

## 既知の制限

- **ギャップに入ったとき、まれに画面のプレビューだけが黒にならないことがある。** 全画面の出力と Spout は黒になる
  （v0.5.0 の検証機で、RTX の 2 時間の試験で 1 回、CPU 内蔵の GPU の周回でギャップ入り 20 回中 2 回。
  この版の候補では RTX の周回のギャップ入り 19 回、内蔵 GPU の HAP の周回の 34 回とも 0 回）。原因を調査中で、
  この版から起きたときにログへ記録する
- ほかは v0.5.0 と同じ
