# TimecodeSyncPlayer v0.5.3

**同期の一時状態が、操作や設定の変更の後に残る問題をまとめて直した版です。** あわせて、ランスルーで保持した後のジャンプの着地が約 2 秒遅れる不具合を直しました。

### 修正

- **ランスルーで LTC が保持された後、同じトラック内でジャンプすると、着地が約 2 秒遅れていた（v0.4.5 から）。**
  保持の間はシークの着地を確かめる機会が無く、シークの保留が 2 秒の時間切れまで残っていた。保持の間も着地を確かめ、
  届かなくなった保留は新しい要求で捨てるようにした。着地までが 1.5〜2.0 秒から約 0.1 秒になった
- **GPU の復旧・トラックの自動送り・ギャップの読み込みで、同期の状態が前のファイルのまま残っていた。** 読み込みの入口をまとめた
- **Single の境界ホールドが、同期を切った後やモードを変えた後も残ることがあった**
- **ロード中の印が、停止や同期の無効化の後も残り、後の無関係な時点で「ロード解除」が起きていた**
- **ジャンプの直後の 1 回だけの適用が、手動シークや同期の有効化の後も抑えられたままになることがあった**
- **読み込みの直後 0.5 秒、前のファイルの着地の目標でシークが抑えられていた**
- **補正モードを Smooth から Jump に変えても、変更前の速度が残っていた。** 手動シークの後に Smooth が使えないままになる件、
  LTC の監視を止めても速度が 1.0 に戻らない件もあわせて直した
- **信号断のモードを停止からランスルーに変えても、止まったままになっていた**
- **損失中のジャンプで復帰した直後に再び無音になると、古い保持値へ着地していた**

### 振る舞いの変化

- 停止モードで LTC がジャンプしてから止まると、映像はジャンプの直後に新しい位置へ移り、止まるときに通り過ぎた分（約 0.25 秒）を戻す。
  これまではジャンプから止まるまで（約 0.3〜0.4 秒）古い位置の絵のままで、止まったときに 1 回で移っていた

## 既知の制限

- **ファイルを足した直後（約 1 秒以内）に一覧の行を選ぶと、選択が外れて「上へ」「下へ」が効かないことがある。**
  長さの読み取りが終わって一覧が更新されるときに選択が外れる。以前の版から。次の版で直す
- **保存したプロジェクトを読み直すと、足した直後に編集したオフセットが 0 に戻っていることがある。**
  同じ原因と見ている（自動試験で 10 回中 2 回）。以前の版から。次の版で直す。当面は、ファイルを足してから 1〜2 秒待ってから
  オフセットを編集し、保存したプロジェクトを読み直してオフセットを確かめる
- **UI を 50ms ごとに読む高頻度の監査（自動試験 U-1）をすると、配信が数秒止まる区間がある。** 通常の操作では起きない。v0.5.1 から
- **ギャップの Freeze で、最終フレームへのシークが素材の終わりと重なると、まれに直前の絵のまま残る。**
  以前の版で 4K の実素材から観測されている型。この版の開発機の試験では出なかった（該当の試験 5 回）。引き続き回数を数える
- ほかは v0.5.2 と同じ
