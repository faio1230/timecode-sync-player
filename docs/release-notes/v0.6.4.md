# TimecodeSyncPlayer v0.6.4

**安定版（Latest）です。**
観測（ログの行）と試験の基盤を整理した版です。同期の判断・再生の動作は v0.6.3 と同じです。ほかの内容・既知の制限・運用の推奨は v0.6.3 と同じです（[v0.6.3 のリリースノート](https://github.com/faio1230/timecode-sync-player/releases/tag/v0.6.3)、[v0.6.1 のリリースノート](https://github.com/faio1230/timecode-sync-player/releases/tag/v0.6.1)）。

v0.6.3 からの移行の注意: 無し（設定・プロジェクトの形式は変わりません）。

### 振る舞いの変化

- 無し（同期の規則・門・定数は v0.6.3 と同じです）

### 表示の変更

- **LTC の FPS が Auto のとき、補正の状態の欄（表示が空いているとき）に「Auto は確認用です。本番は固定にしてください」と表示します。** 補正の状態の表示があるときはそちらを優先します。FPS の選択にツールチップ「本番では LTC の発生器と同じ fps に固定してください」を付けました（項目の文字列は「Auto」のまま）。既定値（Auto）と設定ファイルの形式は変わりません
- セットアップの文書（`docs/SETUP.md`）の Auto の記述に、停止モードで Auto のときは LTC が乱れると約 2 フレーム止まってから 1 回合わせ直すことがある旨を足しました（試験の層での値）

### 観測と試験基盤の変更（動作は変わりません）

- アプリのログに次の行・値を足しました（記録だけで、動作は変わりません）
  - `Sync hold summary`: 止まった判定から出る後ろ向きのシーク（`backwardSeeksWhileStopped`）を、保持中に確定したジャンプの着地（`heldJumpBackwardWhileStopped`）とその他（`otherBackwardWhileStopped`）から分けて数える。行末に `smoothIneffective`
  - `Playback perf`: 行末に GPU の合成が使った新しいフレームの数（`composedSourceFrames`）
  - `Startup timing`: 起動 1 回に 1 行、起動の各段の開始・終了を起動からの経過（ms）で
- 試験の基盤: アプリのログを日付をまたいで読む、前回読んだ位置から続けて読む、一式の前に当日のログを退避する、L-2 の監査で起点の前に始まる区間を数えない、参照の採取の判定を目標の 0〜+1 フレームにそろえる
