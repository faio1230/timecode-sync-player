# TimecodeSyncPlayer v0.6.0（下書き）

**プレリリース（検証中の版）です。本番には安定版 v0.5.4（Latest）を使ってください。**
ProRes の素材を GPU で復号できるようになりました（NVIDIA の GPU で既定で有効）。

v0.5.4 からの移行の注意: 無し（設定・プロジェクトの形式は変わりません。新しい設定 `proResGpu` が無ければ「自動」）。

### 新機能

- **ProRes の GPU 復号**（GStreamer のプラグイン gst-prores-d3d11 v0.2.1 を同梱）
  - 既定（自動）では NVIDIA の GPU でだけ使い、ほかの GPU では従来どおり CPU で復号します
  - 画面の「ProRes の GPU 復号: 自動 / 有効 / 無効」で切り替えます（アプリの再起動の後に反映）。設定ファイルの `proResGpu` と同じです
  - どちらで開いたかは、メタデータ行のデコーダ名で分かります（`V:proresd3d11dec` が GPU、`V:avdec_prores` が CPU）
  - GPU の復号に失敗したとき（プラグインが読めない、GPU が合わないなど）は、CPU の復号に切り替えて開きます。1 回失敗すると、その起動の間は CPU のままです
  - 壊れたフレームがあっても再生は止まりません（ログに記録します）

### 振る舞いの変化

- NVIDIA の GPU の機では、ProRes の素材が既定で GPU で復号されます（v0.5.4 までは常に CPU）。4K の ProRes で使うメモリが約 1.6 GB から約 0.7 GB に減ります（開発機の実測）
- インストーラーは Microsoft Visual C++ 再頒布パッケージ 14.50.35710 以上を求めます。入っている版が古いときだけ、同梱の 14.51 を入れます
- 開発・試験のスクリプトは PowerShell 7 が要るようになりました（利用者が使う `inspect-gop.ps1` は従来どおり Windows PowerShell 5.1 で動きます）

### 既知の制限

- **ProRes の GPU 復号は NVIDIA（RTX 級）で検証しました。** AMD・Intel の GPU は未検証のため、既定（自動）では CPU で復号します。設定で「有効」にできますが、サポート対象外です
- GPU の復号で、壊れたフレームの検出が最大 3 フレーム遅れることがあります（そのフレームの絵はそのまま出ます。プラグインの制限）
- メモリ（システムのコミット）が尽きた環境では、復号のメモリの確保に失敗してアプリが終了することがあります（GStreamer の性質）。空き 4 GB 以上を目安にしてください（SETUP の「推奨環境」）
- ProRes は v0.6.0 では「推奨」の素材ではなく「可」のままです（NVIDIA での「推奨」は検証が済んだ版で）
