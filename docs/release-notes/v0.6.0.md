# TimecodeSyncPlayer v0.6.0

**プレリリース（検証中の版）です。本番には安定版 v0.5.5（Latest）を使ってください。**
ProRes の素材を GPU で復号できるようになりました（NVIDIA の GPU で既定で有効）。

v0.5.5 からの移行の注意: 無し（設定・プロジェクトの形式は変わりません。新しい設定 `proResGpu` が無ければ「自動」）。

### 新機能

- **ProRes の GPU 復号**（GStreamer のプラグイン gst-prores-d3d11 v0.2.1 を同梱）
  - 既定（自動）では NVIDIA の GPU でだけ使い、ほかの GPU では従来どおり CPU で復号します
  - 画面の「ProRes の GPU 復号: 自動 / 有効 / 無効」で切り替えます（アプリの再起動の後に反映）。設定ファイルの `proResGpu` と同じです
  - どちらで開いたかは、メタデータ行のデコーダ名で分かります（`V:proresd3d11dec` が GPU、`V:avdec_prores` が CPU）
  - GPU の復号に失敗したとき（プラグインが読めない、GPU が合わないなど）は、CPU の復号に切り替えて開きます。1 回失敗すると、その起動の間は CPU のままです
  - 壊れたフレームがあっても再生は止まりません（ログに記録します）

### 振る舞いの変化

- NVIDIA の GPU の機では、ProRes の素材が既定で GPU で復号されます（v0.5.4 までは常に CPU）。4K の ProRes で使うメモリが約 1.6 GB から約 0.7 GB に減ります（開発機の実測）
- インストーラーは Microsoft Visual C++ 再頒布パッケージ 14.50.35710 以上を求めます。入っている版が古いときだけ、同梱の 14.51 を入れます。**そのときはインストールの途中で一度だけ管理者の確認（UAC）が出ます**
- 開発・試験のスクリプトは PowerShell 7 が要るようになりました（利用者が使う `inspect-gop.ps1` は従来どおり Windows PowerShell 5.1 で動きます）

### 修正

- v0.5.5 の修正（Single モード・RunThrough で、LTC がクリップの外で止まったままトラックを読み込む・切り替えると、クリップの出口を越えて再生が続くことがあった）を含みます

### 既知の不具合

- LTC の信号が乱れた直後に、位置を合わせ直すシークが続けて出て、重い素材（4K や 60p。H.264 でも ProRes でも）で最大 0.6 秒ほど映像が止まることがあります。v0.5.4 から同じです。v0.6.1 で修正します
- プレイリストにファイルを足した直後（長さの読み取りが終わるまで。本数に比例して数秒〜）に一覧の行を選ぶと、読み取りの完了時に選択が再生中の行（空から足したときは先頭）へ戻ることがあります。そのまま「上へ」「下へ」「削除」を押すと、再生中の行に効きます。選び直せば正しく動きます（v0.5.4 以前から。2026-10-01 訂正）
- LTC の大きな Jump の直後に後ろ向きの位置合わせが起きた後、映像が約 1.5 秒黒になったことが v0.5.5 の検証機で 1 回ありました。v0.6.0 の検証では出ていません。原因は切り分け中です（試験の画面の記録に別の窓が重なった可能性も残ります）。v0.6.x で追います

### 既知の制限

- **ProRes の GPU 復号は NVIDIA（RTX 級）で検証しました。** AMD・Intel の GPU は未検証のため、既定（自動）では CPU で復号します。設定で「有効」にできますが、サポート対象外です
- GPU の復号で、壊れたフレームの検出が最大 3 フレーム遅れることがあります（そのフレームの絵はそのまま出ます。プラグインの制限）
- メモリ（システムのコミット）が尽きた環境では、復号のメモリの確保に失敗してアプリが終了することがあります（GStreamer の性質）。空き 4 GB 以上を目安にしてください（SETUP の「推奨環境」）
- VC++ 再頒布パッケージが 14.50 より古い PC では、インストールの途中で一度だけ管理者の確認（UAC）が出ます。無人でインストールするときは、先に VC++ 再頒布パッケージ（14.50 以上）を入れておいてください
- ProRes は v0.6.0 では「推奨」の素材ではなく「可」のままです（NVIDIA での「推奨」は検証が済んだ版で）

### 検証の概要

公開したビルドは、検証機で試した候補 2（`0.5.5+b1b5bab`）と製品のコードが同じで、版番号と文書だけが違います（配布物の違いは版の表記を含むファイルだけ。下の「配布物」）。候補 1（`0.5.4+e086e2e`）は検証機で 2 件落ち、1 件（Single モードの出口の件）は直して候補 2 に、もう 1 件は上の既知の不具合の 1 つ目です。

- **開発機**（2026-09-30、RTX 3070）
  - 非E2E 2,865 件合格 / 0 失敗
  - LTC シナリオの一式（候補 2 と同じ製品のコード）: 標準 ×2・重い素材（H.264 4K 59.94 ほか）・ProRes ×2（ProRes 4K 59.94・1080p 59.94）がそれぞれ 24 件合格 / 0 失敗、連続追従 ×2 合格。ProRes のロードは 2 回とも 142 件すべて GPU、CPU 0、アダプタの不一致 0
  - GPU と CPU の復号の色の差（試験パターン、4K と 1080p）: 平均 0.58〜0.67（8bit）。アルファ付きの 4444（試験パターン）は RGB・アルファとも差が最大 1
  - 壊れたフレーム、プラグインの外れ、`.cso` の欠け、アダプタの不一致の強制: どれも止まらず CPU の復号に切り替わるか、そのまま再生を続ける
- **検証機**（2026-10-01 03:32〜、RTX と内蔵 AMD の Optimus、実素材 M1〜M7 と ProRes の PR1〜PR4、利用者の操作が無いことを確かめてから開始）
  - インストール: 3.8 秒（VC++ はすでに新しく、追加なし）。最初の起動 3.13 秒で止まりなし
  - 事前確認 6/6
  - 標準のシナリオ 3 通り（うち 1 通りは本番と同じ構成: インストール版・トレース無し）: それぞれ 38 件合格 / 0 失敗
  - 連続追従 6 本合格。トラックの切替 2 本のうち 1 本は、LTC の乱れた回で既知の不具合の 1 つ目（最大 0.58 秒）
  - ProRes: RTX では 356 回のロードがすべて GPU、CPU 0、アダプタの不一致 0（HQ 4K60、Standard 1080p60・2560x1536p60、4444 アルファ 4K30）。内蔵 AMD では既定どおり 76 回すべて CPU で、シナリオ 38 件合格 / 0 失敗
  - GPU と CPU の復号の色の差（実素材、同じ位置の 1 フレーム）: 平均 0.28〜0.51、p99 1〜6（8bit）。判定の基準（平均 1.0 以下・p99 10 以下）の内側
  - 非E2E 2,865 件合格、E2E（アプリを起動するもの）59 件合格
- **配布物**: 候補 2 の zip とファイル単位で比べ、違うのは版の表記を含むファイル（exe・dll・deps.json・README.txt・CHANGELOG）だけ。shim（`tcs_gstreamer.dll`）は候補 2 と同じ
