# TimecodeSyncPlayer v0.5.0

**HAP を GPU で直接再生できるようにした版です。** VJ でよく使われる HAP（Hap・Hap Alpha・Hap Q）を、
CPU で展開して 1 コマ 33MB を転送するのではなく、圧縮したまま GPU へ渡して展開します。
4K60 の Hap Q でも CPU の負担はほとんどありません。

あわせて、検証の中で見つかった**Single モードでクリップの端を扱うときの不具合 3 件**（以前の版からあったもの）と、
性能の記録の不具合を直しました。

### 追加

- **HAP の再生（Hap・Hap Alpha・Hap Q）。** 設定は要りません。読み込むと GPU で展開して再生します
  - 圧縮したテクスチャを GPU へ渡し、GPU 上で絵に戻します。CPU で展開する経路には流しません（4K では間に合わないため）
  - Hap 7 と Hap HDR は、色の戻し方が違うため**読み込み時に理由を出して断ります**（黙って違う色の絵を出さない）
  - Hap Q Alpha は、実際のソフトで書き出した素材で確かめるまで**未保証**です（手元の ffmpeg では書き出せないため）
  - 止めたいときは、起動前に環境変数 `TCS_HAP=off` を設定します
  - HAP は全フレームがキーフレームなので、読み込み時のキーフレーム間隔の解析はファイルを読まずに済ませます
  - HAP はファイルが大きいので、**素材は内蔵の SSD（NVMe）に置いてください**（4K60 の Hap Q で毎秒 数百 MB）

### 修正（以前の版からあったもの）

- **Single で、クリップの出口で止めたまま LTC が入口ちょうどに戻ると、出口に取り残されていた。**
  LTC を戻しても映像が動かなかった（MediaIn を設定したクリップで、LTC が MediaIn ちょうどに来たとき）
- **Single で、LTC がクリップの入口より手前に来ると、入口へ移らずにその場で止まっていた。**
  読み込み直後の位置（クリップの外）の絵のまま止まった。いまは入口の絵へ移ってから止まる。
  信号断の「停止」で止めた値へ着地するときも、クリップの外へ着地していたのを直した
- **クリップの終わりが素材の終わりと同じとき、終わりへのシークで位置が定まらなかった。**
  素材の終わりちょうど（最後のコマの後）を狙っていたため。いまは最後のコマへ着地する
- 性能の記録（`Playback perf`）の最初の 2 秒の区切りが、読み込みや先頭の暗転をまたいで 5〜6 秒に伸びることがあった
  （記録だけの問題。「デコードが追いついていません」の表示には影響しない）

### 整理（振る舞いは変わらない）

- 受け取った処理を呼ぶだけのクラス 2 つと、置き換え済みだった古いキーフレーム警告の経路（`TCS_LONG_GOP_WARNING`）を削除した

## 検証の概要

- **開発機**（2026-09-24、Debug）
  - 非E2E **2109 件合格 / 0 失敗**。HAP の解析・展開のテスト（実データ 4 通り）も合格
  - HAP の素材と、MediaIn / MediaOut を持つクリップで、Single のシナリオ（S 系）を回して合格
- **検証機**（2026-09-23〜24、候補 4 `5861a32`、ノート PC、CPU 内蔵の GPU と RTX 3080 の両方）
  - HAP の素材は実素材（M1・M4・M7）から作った 4K60 の Hap Q・Hap（4 分割あり・なし）と 1080p60 の Hap Alpha、
    ノイズの 4K60 Hap Q（毎秒約 500MB 読み出し）
  - **HAP のシナリオ一式（38 項目）を内蔵 GPU と RTX で 2 組ずつ、4 回とも合格**。同じトラックの中で跳ぶ試験を
    単独で 5 回、すべて合格。「デコードが追いついていません」0 件、エラー 0 件
  - **絵**: ffmpeg で展開したコマと比べて、狙ったコマがいちばん近く、色の差は 1/255 未満。内蔵 GPU と RTX で同じ絵
  - **開始直後**: 内蔵 GPU で分割ありの 4K60 Hap Q を開いた直後の 2 秒は、途中の候補では 106〜118 コマに落ちていたが、
    展開の処理を直して 121 コマ（期待 120）
  - **既存の形式への影響**: 実素材（H.264・ProRes）の標準セット（シナリオ 3 通り・連続追従 6 本）を v0.4.8 と交互に回し、
    この版はシナリオの失敗 0、連続追従 12 本すべて合格（最大誤差 0.062〜0.078 秒、v0.4.8 は 0.067〜0.083 秒）
  - **HAP を既定で有効にした最終の候補（`a820a5e`）**: 環境変数なしで HAP のシナリオ一式（内蔵 GPU）37 件合格、
    `TCS_HAP=off` では読み込みを断る、H.264 の実素材のシナリオ（RTX）37 件合格で HAP の経路には入らない

## 既知の制限

- Hap Q Alpha は未保証（上記）。Hap 7・Hap HDR は読み込まない
- CPU 内蔵の GPU では、4K60 の H.264 を実時間で復号しきれないことがある（v0.4.8 と同じ。現場準備ガイドの「既知の制限」）。
  HAP は内蔵 GPU でも 4K60 で落ちずに再生できた
- トラックを切り替えた直後は、読み込みにかかった時間ぶんタイムコードより手前から始まり、1 秒前後で追い付く（以前から。v0.5.1 で扱う）
- ほかは v0.4.8 と同じ
