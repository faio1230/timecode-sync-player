# VB-CABLE モンキーテスト

操作順をseed（乱数の初期値）で固定し、アプリを実際に操作する耐久テストです。操作の途中でLTCを止めたり飛ばしたりし、最後に受信・再生が復帰して正常終了することまで確認します。操作ログを使って同じ順序を再実行できます。OSや音声スレッドのタイミングは毎回変わるため、競合の完全再現を保証するものではありません。

対象は再生切り替え、3連続シーク、前後の曲、同期ON/OFF、LTC受信開始停止、同期・Gap・信号断モード、LTC停止・再開・ジャンプ・ノイズの13種類です。事前に実際の空白区間でBlack/Freeze両方を確認します。最後の同期復帰は、単なる再生位置の増加ではなく、その時点の受信LTCとの誤差で判定します。

## 準備

1. Windowsの対話デスクトップで実行してください。実行中はテスト用アプリを操作せず、ロック・スリープを避けてください。他のE2Eテストとの同時実行も避けます。
2. VB-CABLEの再生デバイス **CABLE Input** と録音デバイス **CABLE Output** が有効であることを確認してください。テストは送信先・受信元を名前で明示選択するので、Windowsの既定デバイスを変更する必要はありません。VB-CABLEは入力された音声を出力側へ運ぶ仮想ドライバーです。[公式配布・説明](https://vb-audio.com/Cable/)
3. 同じCABLE Inputへ別の音楽やLTCを送信しているアプリは止めてください。今回のテスト自身がLTCを生成するため、外部送信ソフトは不要です。
4. .NET 8 SDK、PowerShell 7.2以上（`pwsh`）、ffmpeg、`native/`内のmpv DLLが必要です。動画はテスト用の720p/30fps/H.264素材を自動生成します。通常の準備は[SETUP.md](SETUP.md)も参照してください。

2026-09-07のこの開発PCでは、既存の実機テストでVB-CABLE受信・進行・停止を確認済みです。

## 実行

リポジトリのルートでPowerShell 7から実行します。現在の作業内容をビルドして、そのリポジトリのEXEだけを起動します。

```powershell
# 標準: 3種類のseed、それぞれ250操作。1回の上限15分。
./scripts/run-timecodesyncplayer-monkey.ps1

# 最初の接続確認
./scripts/run-timecodesyncplayer-monkey.ps1 -Seeds 4242 -Actions 20

# 同じ操作列を再実行（失敗したseed・操作数を指定）
./scripts/run-timecodesyncplayer-monkey.ps1 -Seeds 4242 -Actions 250

# 操作数を増やす。これは実行例であり、実施済みの保証ではありません。
./scripts/run-timecodesyncplayer-monkey.ps1 -Seeds 4242,1701,9001 -Actions 10000 -TimeoutMinutes 120
```

通常の `dotnet test` ではこの長時間試験はスキップします。スクリプトは明示的に有効化し、Monkey分類だけを実行します。有効化したのに前提不足で実行できなかった場合や、スキップ・結果欠落は成功になりません。各試験は別プロセスで、設定も通常利用から隔離します。上記の長時間例は操作数ベースであり、指定分数だけ走り続ける意味ではありません。

## 結果と停止判定

結果は `TestResults/monkey/<日時と実行ID>/<連番とseed>/` に保存されます。

| ファイル | 内容 |
| --- | --- |
| `monkey.jsonl` | 操作開始・結果・パラメータ・実行中の観測。末尾から止まった操作を特定 |
| `summary.json` | テスト自身の成否と操作数 |
| `app-process.json` | 起動したアプリの識別情報。後始末は同じID・起動時刻・EXEだけが対象 |
| `monkey.trx` | テストランナーの合否 |
| `stdout.log` / `stderr.log` | テストランナー出力 |
| `app-*.log` | この試験中に追加されたアプリログ。ERR/FTLがあれば監視側でも失敗にする |
| `supervisor.json` | 外側の監視結果。時間切れや操作履歴の停止も失敗として記録 |
| 親フォルダの `runs.json` | seedごとの集計 |
| 親フォルダの `environment.json` | 設定、コミットと実行バイナリのSHA-256（未コミットのビルド差も識別） |
| `fixture.tsp` / `clip-*.mp4` | 実行に使ったプロジェクトと生成素材。20秒の動画2本、間に5秒の空白 |

既定では履歴更新が60秒止まるか、1回の試験が15分を超えると、その試験で起動したプロセスツリーを停止して失敗にします。最初の履歴生成には最大120秒の準備時間を設けています。途中の結果は残し、失敗したseedで停止します。外側の監視はPowerShell自体を強制終了した場合には働きません。

同じseedに加えて、アプリのコミット・DLL・動画・音声設定も揃えると調査しやすくなります。通常のアプリログは対象EXE隣の `logs/` にあり、この試験中の追記分も結果先に保存します。メモリ・ハンドル数は傾向を調べる観測値です。短時間の増減だけでリークの有無は断定しません。

## 次に本番条件で準備してほしいもの

- 本番と同じ解像度・fps・コーデックの素材。特に最も重い動画と、多数の短いクリップを含むプレイリスト。まず条件と保存場所を共有してください。
- 実際に使うLTCのfpsと送出ソフト。自動試験の25fpsに加え、本番の設定でも検証します。
- Spoutを使う場合は受信ソフトと本番同様の出力先・解像度。送信ボタンの操作だけでは、受信映像の正しさまで検証できません。
- 本番に近い長さの連続試験を行える、PCを操作せずに置ける時間。

この試験が通っても「どんな使い方でも絶対に落ちない」とは言えません。USB音声機器の抜き差し、ドライバーの無効化・再有効化、スリープ復帰、GPUやSpout受信側の障害、本番素材のデコードは別の検証項目です。

## 実測結果

2026-09-07、Debug、720p/30fps/H.264の20秒動画2本、間隔5秒、LTC25fps、VB-CABLE 48kHz/2chで実行しました。

| seed | 試行数 | 操作実行 | 無効で見送り | 監視を含む所要時間 | 復帰・正常終了 |
| --- | ---: | ---: | ---: | ---: | --- |
| 4242 | 250 | 230 | 20 | 89.78秒 | 合格 / 終了コード0 |
| 1701 | 250 | 239 | 11 | 86.02秒 | 合格 / 終了コード0 |
| 9001 | 250 | 242 | 8 | 90.28秒 | 合格 / 終了コード0 |

750試行・711操作を実行し、13種類すべてを含みました。シーク連打は56回（各3シーク）。無効なコントロールは操作せず履歴に残しています。「実行」は入力を送った回数であり、同じモードを再選択した場合など、毎回状態が変わるとは限りません。3回ともBlack/Freeze事前検証、LTC進行、通常再生、同期復帰、LTC受信中の正常終了に合格。アプリログのERR/FTLは0件です。

結果: `TestResults/monkey/20260907-121616-2d5cd675/`。対象アプリの修正コミットは `af8aba0`、試験コードは `61ce8c4`。プロセスメモリの観測ピークは約529/525/548MiB、ハンドルのピークは1148/1161/1151。約4分半の試験なので、長時間リークの有無は未判定です。

検証中に、ContinueからSingleへ戻した際に曲名表示が更新されない経路を検出しました。専用の回帰テストで失敗を再現し、モード変更時に表示を必ず更新するよう修正しました。別途、試験側の乱数の偏り・同期復帰判定・素材配置もレビューで修正しています。

通常の非E2Eテストは1215件すべて合格。明示有効化しない場合はMonkeyテストが1件スキップされ、アプリを起動しないことも確認済みです。テスト結果は `TestResults/monkey-non-e2e.trx` と `TestResults/monkey-opt-in.trx` に保存しています。

既存E2EもMonkey分類を除いた50件すべて合格（失敗0・スキップ0、2分57秒）。結果: `TestResults/monkey-regression-e2e.trx`。通常テストは計1265件合格です。最終ビルドは警告0・エラー0、独立レビューの修正必須指摘は解消済みです。

監視処理自身も、seed777・要求100000操作・上限1分で故意に時間切れにしました。60.29秒で失敗を記録し、所有アプリが残らないことを確認しています。これは監視機能の異常系試験であり、100000操作を完了したという意味ではありません。結果: `TestResults/monkey-watchdog-check/20260907-122059-41e8a546/`。履歴停止タイムアウトはコードレビューで確認していますが、今回の故意停止は総時間上限に対する試験です。
