# GPU出力の初回実証仕様

2026-09-09。ユーザーの「それでは続けてください」により、検証用アプリの実装と初回評価へ進む。合意した運用・機能仕様は [OUTPUT-PIPELINE-DESIGN.md](OUTPUT-PIPELINE-DESIGN.md)。本体へのGPU移行、mpv接続、複数全画面、GPUプレビューの組み込みはこの初回実証の後に判断する。

実装と初回比較は完了。[実証結果](GPU-OUTPUT-PROBE-RESULTS-2026-09-09.md)に、表示寸法の確認、8回の4Kキャンバス比較、受信画像の証拠、次に切り分ける取得方式を記録した。本書はその比較に使用した初期条件を残す。

## 範囲と配置

- `scripts/GpuOutputProbe/` に独立した .NET 8 / WPF / x64 の検証用アプリを作る。Debugで実行する。本体プロジェクトへの参照・本体コードの変更は不要。
- Direct3D 11 / DXGI / HLSLを使用。C#の呼び出しには.NET 8対応を確認したVortice 3.6.2系を候補とし、具体的なパッケージと対応APIをビルドで確認する。
- 手元の `native/SpoutDX.dll` を使う。既存のC++クラスP/Invoke方式を起点に、確認済みSendTextureエクスポートを追加する。既存本体バインドの動作は変更しない。
- 対応するSDK配布MT版DLLとのSHA-256一致を確認。付属ヘッダーをMSVC x64 /MT /D_ITERATOR_DEBUG_LEVEL=0 /DSPOUT_IMPORT_DLLでCPUのみのsizeofプログラムへコンパイルした結果、`sizeof(spoutDX)=1864`、alignment=8、pointer=8。既存の4096バイト確保はこのサイズを上回る。証跡は `TestResults/gpu-output-abi-20260909-185707/`。実動作の確認は別途行う。
- 映像入力はGPU生成パターンのみ。動く目印、フレーム番号を識別する図形または数字、色帯・外枠を描く。表示にテクスチャのCPU読み戻しを使わない。
- BGRA8 UNORM、不透明、SDRを最初の試験形式とする。HDRや汎用シェーダー編集機能は追加しない。

## コマンドと操作

予定CLIは `--mode common|split --output fullscreen|spout|both --width 1920 --height 1080 --fps 60 --seconds 32 --warmup 5 --log-dir <新規ディレクトリ> --sender <一意名>`。

- 表示先は `--monitor-index` で明示できるようにする。`--list-displays` の読み取り用列挙を用意し、実解像度・配置・更新周波数等を記録する。初回スモークにはウィンドウ表示を選べるようにする。
- 操作ウィンドウはWPF、映像表示はHWNDへDirect3Dで行う。GPU処理と終了待ちはWPFスレッド上で行わない。
- 指定秒数終了は処理受付を止め、所有スレッド上で完了待ち・解放する。UI操作で閉じる場合は継続・通常終了・強制終了の選択を示し、キャンセルを初期選択にする。強制終了はそのアプリ自身のみ、追加確認なし。通常終了の待機中も選択可能。
- 設定保存・既存ログの利用・既存アプリの終了をしない。実行ログは新規ディレクトリに出し、既存ファイルへの上書きを拒否する。

## 所有するスレッドと資源

| 資源 | common | split |
| --- | --- | --- |
| 合成デバイスと即時コンテキスト | GPUワーカー | GPUワーカー |
| 3枚の合成画像・描画用ビュー | GPUワーカー | GPUワーカーで作成 |
| 全画面スワップチェーン | GPUワーカー | GPUワーカー |
| Spout用デバイスと即時コンテキスト | 合成デバイスを共用、GPUワーカーのみ操作 | 同じアダプター上の別デバイス、送信ワーカーのみ操作 |
| Spout送信用保持画像1枚 | GPUワーカー | 送信ワーカー |
| Spoutインスタンス・外側の名前付きmutex | GPUワーカー | 送信ワーカー |
| 時刻・フレーム番号等のメタデータ | 短い管理ロックで共有 | 短い管理ロックで共有 |

同じ即時コンテキストを複数スレッドから操作しない。別デバイスの作成時は合成側とアダプターLUIDを照合し、不一致なら試験を開始しない。

両モードともSendTextureの前に送信用保持画像へのGPUコピーを行う。同一画像の再送ではコピーを省略する。この比較はGPU内コピーを両モードに含め、スレッド・デバイス間共有と同期の追加費用を含む構成比較とする。

## 画像の公開と再利用

- 合成画像プールは初期3枚。用途は最大で「Spoutへのコピー元として使用中」「最新公開」「次の合成」。全画面は合成側と同じワーカーで順次処理し、描画に使用した元画像のGPU使用完了を確認してから次の処理へ進む。初回には独立したプレビュー読者を追加しない。
- 各領域をCPU側の状態・使用権でも管理する。最新画像の取得と使用権取得を同じ短いロックで行う。GPU操作・完了待ち・Spout呼び出し中にこの管理ロックを保持しない。
- 作成中の画像は公開しない。HLSL描画の後にD3D11 EVENT queryをEndし、Flush後に完了確認してから最新として公開する。初回実証では同期費用を明示的に測れる保守的な方式を優先する。
- 空きがなければその回の生成を見送り、次の予定時刻の状態から生成する。古い未使用画像を待ち行列へ蓄積しない。フレーム番号と生成時刻は画像に付けて最後まで維持する。
- splitで共有するテクスチャはSHARED_KEYEDMUTEXを使用し、共有ハンドルを送信側デバイスで一度開いて保持する。legacy共有ハンドルをNTハンドルと同じ扱いでCloseHandleしない。
- 資源へのGPUアクセスにはAcquireSync(0, 0)／ReleaseSync(0)を使用する。所有するCPU側使用権と組み合わせ、複数デバイスが同じ画像へ同時アクセスしない。S_OK、WAIT_TIMEOUT、WAIT_ABANDONEDを明示的に区別する。符号だけで成功判定しない。
- 共有画像を取得できなければ、その回の取得をスキップする。Spoutに保持画像があればそれを再送する。
- 送信用保持画像へのCopyResource後、EVENT queryでコピー完了を確認し、共有画像のkeyed mutexと使用権を返してからSendTextureを呼ぶ。これによりSpoutの送信待ち中に合成画像を保持しない。
- 全画面も、共有画像を使って表示先へ描画した後、元画像のGPU使用完了を確認してロックを返し、その後Presentする。全画面の表示用バッファは合成画像と別に数える。
- shared textureを使わないcommonでも、公開・使用権・コピー完了の意味は揃える。GPU完了を省く最適化は初回比較の後に判断する。

## Spoutの公開境界

SendTextureのtrue復帰だけを、共有画像更新の証明にしない。SDK内にはmutexを取得できず送らなかった場合もtrueとなる実装がある。

- CheckSenderで準備し、実際の登録名から `<name>_SpoutAccessMutex` を開く。
- 外側のOS mutexを待ち時間ゼロで取得する。取れなければその回の送信をスキップする。
- 同じ所有スレッドでSendTextureを呼び、送信側EVENT queryの完了まで外側mutexを保持する。SDK内部の再帰的なmutex取得・解放と整合させる。
- 送信API復帰、GPUコピー完了、外側mutex解放の時刻を区別する。共有画像の公開完了を、受信アプリでの異なる画像の到達や物理表示と同一視しない。

## 周期と全画面

- Stopwatch/QPCに基づく予定時刻を使用し、初期60Hz。遅れた回を連続実行して取り戻さない。予定時刻のスキップ数を数える。
- commonは単一ワーカーで合成・全画面・送信を実行する。splitは合成・全画面と送信が同じ開始基準時刻を持ちながら別々に進む。
- Presentはティアリングを許可しない。flip modelとframe latency waitable objectを使う候補とし、画面の準備ができていない場合はその回の描画をスキップする。実際のPresent時間も測る。
- 全画面はキャンバス全体を縦横比維持・中央揃え・黒余白で表示する。キャンバス寸法と実表示寸法・リフレッシュレートを別々に記録する。

## エラーと終了

- GPU queryが100ms経っても未完了なら異常を記録し、新規処理を停止する。時間超過を根拠に画像を再利用・破棄しない。所有スレッドは使用終了の確認を続け、UIは応答可能にする。
- デバイス無効の確定と単なる未完了を区別する。使用中のネイティブ呼び出しへ別スレッドからDisposeを割り込ませない。
- 初回の性能実証は異常を隠して継続しない。本体で合意した一度の自動復旧は、実証中に測定を無言で再開する根拠にしない。
- 実GPUの強制リセット、WPR、UACを伴う記録、他プロセスへの操作を行わない。

## 記録と初回評価

- フレームごとに予定・生成開始・GPU合成完了・公開、コピー開始／完了、Present開始／復帰、SendTexture開始／復帰、Spout公開完了、画像ID、スキップ理由を記録する。
- 描画ワーカーからの同期ファイル書き込みを避け、件数上限付きの記録を終了後に保存するか専用書き込み経路へ渡す。上限超過は明示し、ログ欠落の試験を有効な性能結果として扱わない。
- `manifest.json`、`events.jsonl`、`summary.json` を新規ログディレクトリへ出す。manifestはCLI条件・QPC周波数・アダプター・実表示条件・DLLハッシュを含む。
- 1080pで短いスモークの後、4Kキャンバス・60Hz・32秒の試験を基本とする。開始後5秒以上27秒未満を22秒の解析窓にして以前の試験の区間と合わせる。ただし今回はGPU生成画像なので旧mpv試験との性能差をGPU移行効果として直接比較しない。
- 単独全画面、単独Spout、併用をcommonとsplitで直列実施。併用を比較の中心とし、有望な方式を反復確認する。ネイティブ異常が出た場合は原因確認前に負荷を上げたり反復したりしない。
- 親エージェントが公式WinSpoutDXreceiverを使って試験する。自分で起動したPIDだけを管理する。受信の画像ID確認が目視に留まる場合はその限界を明記する。
- 指定の公式WinSpoutDXreceiverの公開ソースではReceiveImageとGDI表示を使用する。送信側をGPU経路にしても、この受信機側にはCPU読み戻しが残る。タイトルだけでは実送信名への接続を証明できないため、受信プロセスの生存と実受信画像の確認を別の証拠として扱う。
- 評価は公開頻度、間隔p95/p99/最大、生成から出力開始までの経過時間、出力間ID差、再送／スキップ、警告・エラーを比較する。平均60fpsだけで採用を決めない。

## 実装の検証

スケジューラーの遅延後のスキップ、最新画像の置換と使用権、使用中画像の再利用拒否、GPU完了前の返却拒否、失敗時の終了状態を管理テストで確認する。GPU・Spoutの実動作は親が直列で実施し、エージェントによる実機試験の並行実行は禁止する。
