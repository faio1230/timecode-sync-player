## 項目ごとの変更

### 1. 入手スクリプト（`scripts/get-prores-plugin.ps1`、csproj）

- zip の `LICENSE`・`README.txt`・`SHA256SUMS.txt` を `native\gst-prores\licenses\` に置く。DLL と `.cso` は今のまま直下
- 照合は関数 `Assert-ProResPluginFiles` 1 つ: DLL の SHA-256 を固定値と比べる → `SHA256SUMS.txt` の DLL の行が固定値と一致することを要求（`.cso` の値を固定の版に結びつけるため）→ `SHA256SUMS.txt` の `prores_*.cso` が 6 行、フォルダの `prores_*.cso` が 6 個、各 SHA-256 が一致。違えば throw
- 照合は展開した zip の中身と、置いた後の `native\gst-prores` の両方に掛ける
- 引数 `-VerifyDir <dir>` を足した: ダウンロードせず、置き済みのフォルダ（`native\gst-prores` と同じ形、`licenses\` の 3 ファイルを含む）だけを照合する。`package-release.ps1` はこれを呼ぶ。**固定値（版・URL・zip と DLL の SHA-256・`.cso` の数）は `get-prores-plugin.ps1` の先頭の 1 か所のまま**で、パッケージのスクリプトに重複させていない
- csproj: `native\gst-prores\*` → `native\gst-prores\*.dll;native\gst-prores\*.cso`（`licenses\` を bin に入れない）。Debug の bin の `gst-extra-plugins\` は DLL 1 と `.cso` 6 だけ（確認済み）

### 2. パッケージ（`scripts/package-release.ps1`）

- 引数 `-ProResPluginDir`（既定 `native\gst-prores`）。**ビルドの前に** `get-prores-plugin.ps1 -VerifyDir` で照合し、失敗なら「ProRes の GPU 復号プラグインを照合できませんでした…」で止める
- staging の `gstreamer\lib\gstreamer-1.0\` へ `gstproresd3d11.dll`（名前はそのまま）と `prores_*.cso` 6 個、`gstreamer\share\licenses\gst-prores-d3d11\` へ `LICENSE` と `README.txt`。コピーの後に元と写しの SHA-256 を比べる
- **Release 出力のサブディレクトリの検査から `gst-extra-plugins` を外した**: csproj が Release でも `native\gst-prores` を `bin\Release\...\gst-extra-plugins\` へコピーするため（実際に出来ていた）、外さないと既存の検査（サブディレクトリがあれば止める）で必ず止まる。staging は直下のファイルしかコピーしないので、配布物には入らない（zip の一覧で `gst-extra-plugins` は 0 件）
- README.txt の雛形: 要件の行を `Microsoft Visual C++ 2015-2026 Redistributable (x64) 14.50.35710 or later`、入手先を `https://aka.ms/vc14/vc_redist.x64.exe` に。ProRes の GPU 復号の 3 行（NVIDIA で既定有効、他のベンダーは既定で CPU、`proResGpu` の auto / on / off、再起動で反映）

### 3. VC++ 再頒布パッケージ 14.50.35710 以上

- 固定値は `package-release.ps1` の先頭の 1 か所: `$vcRedistMinVersion = 14.50.35710`、`$vcRedistPinnedVersion = 14.51.36247.0`、`$vcRedistPinnedSha256`、`$vcRedistPinnedUrl`。`-VcRedistUrl` の既定は固定の URL（引数を空にして後で埋める）
- 更新の手順はスクリプトの先頭のコメントと `docs/RELEASE-PROCEDURE-0.4.md` の 1 節に書いた
- `Resolve-VcRedist`: 署名の検査（今のまま）→ `VersionInfo.ProductVersion` を `[Version]` で読み、最低版未満なら止める → キャッシュのときは SHA-256 が固定値と違えば止める。止まるメッセージに更新の手順の場所と固定の版・SHA・URL を出す。`-VcRedistPath` で渡したファイルは署名と最低版だけを見て、SHA-256 はログに出す。ダウンロードは `.partial` に落としてから改名
- **ISCC と再頒布パッケージの解決をビルドの前に移した**（`-SkipInstaller` でないとき）。古い再頒布パッケージで zip だけ出来て止まる、を避けるため
- `installer.iss`: 最低版を `/DVcMinMajor`・`/DVcMinMinor`・`/DVcMinBld` で受け取る（無ければ `#error`）。`[Run]` の StatusMsg を最低版の表記に

`[Code]` の比較（`scripts/installer.iss`）:

```pascal
function VcRuntimeMissing: Boolean;
var
  Installed, Major, Minor, Bld: Cardinal;
begin
  Result := True;
  if not RegQueryDWordValue(HKLM64, VcRuntimeKey, 'Installed', Installed) then Exit;
  if Installed <> 1 then Exit;
  if not RegQueryDWordValue(HKLM64, VcRuntimeKey, 'Major', Major) then Exit;
  if not RegQueryDWordValue(HKLM64, VcRuntimeKey, 'Minor', Minor) then Exit;
  if not RegQueryDWordValue(HKLM64, VcRuntimeKey, 'Bld', Bld) then Exit;
  if Major <> {#VcMinMajor} then Result := Major < {#VcMinMajor}
  else if Minor <> {#VcMinMinor} then Result := Minor < {#VcMinMinor}
  else Result := Bld < {#VcMinBld};
  Log(Format('VC++ runtime x64 installed %d.%d.%d, minimum ..., install=%d', [...]));
end;
```

（実物は 1 行ずつ改行。`VcRuntimeKey = 'SOFTWARE\Microsoft\VisualStudio\14.0\VC\Runtimes\x64'`）

- 読み: キーか値（`Installed`・`Major`・`Minor`・`Bld`）が 1 つでも読めない、`Installed<>1`、または `Major.Minor.Bld` が 14.50.35710 より小さい（上の桁から順に比べる辞書順）とき True → 同梱の再頒布パッケージを `/install /quiet /norestart` で実行する。例: 14.44.35211 → Minor 44<50 で True。14.50.35709 → True。14.50.35710・14.50.35719・14.51.x・15.x → False
- Inno Setup 6.7.3 のコンパイルは通った（`Compiling [Code] section` → `Successful compile`）。**実際のインストールはしていない**
- 開発機のレジストリ（読むだけ）: `Installed=1`、`Major=14`、`Minor=50`、`Bld=35719`（→ この関数では False＝入れない）

## 未解決の点・気づいたこと

1. **README の要件の行の名前**: 指示書の文言「2015-2026」で書いたが、Microsoft の 14.51.36247 のファイルの説明は「Microsoft Visual C++ v14 Redistributable (x64)」だった（14.44 は「2015-2022」）。利用者が検索するときの名前と違う可能性がある
2. **固定の URL の寿命**: 版ごとの転送先 URL（`download.visualstudio.microsoft.com/download/pr/…`）がいつまで残るかは確かめていない。消えたらダウンロードが失敗して止まり、更新の手順（`aka.ms/vc14` の転送先を確かめて固定値を書き換える）になる
3. 最低版（14.50.35710）と固定の版（14.51.36247.0）が違う。固定の版は 2026-09-30 に `aka.ms/vc14` が返したもので、14.50 系そのものの再頒布パッケージを返す Microsoft の URL は見つけていない（`aka.ms/vs/17` は 14.44、`aka.ms/vs/18` と `aka.ms/vc14` は 14.51）
4. `-VcRedistPath` で渡したファイルは SHA-256 を固定値と比べない（署名と最低版だけ）。渡したものを使う用途のため。SHA-256 はログに出る
5. インストーラーは実際に走らせていない。`PrivilegesRequired=lowest` で `vc_redist.x64.exe` を `shellexec` で起動する形（昇格の確認が出る）は今までのまま
6. csproj は Release でも `gst-extra-plugins\` をコピーするので、パッケージ側で検査から外した。csproj の条件（Debug だけ）で止める案は、Release の bin から直接起動したときのプラグインの探索（2-4）を変えるので取らなかった
7. 退避したもの: `artifacts\cache\vc_redist.x64.exe.14.44.35211-stale`（14.44）、`artifacts\release\*.stage4-check`（確認用の成果物）。scratchpad に試験用の写しと 2 つの再頒布パッケージ
8. PowerShell 7 化（段 5）は範囲外。今回の `.ps1` は 5.1 で動かした
