## 親が実機で確かめる手順の案（段 2 の shim と合わせたとき）

前提: 段 2（担当 A）の shim を Debug でビルドし、このブランチと合わせたツリーで。`TCS_PRORES_GPU` は設定しない（設定より優先されるため）。

1. 設定ファイルの `proResGpu` を消した状態（または `"auto"`）で起動 → アプリのログに `GstBackendState: proResGpu=auto を shim に設定しました`、tcs-gst のログに `prores-gpu: mode=auto source=setting vendor=0x10de -> enabled`。UI は「自動」、案内なし
2. ProRes 4K60 を 1 本ロード → `load.summary ... profile=prores-gpu`、メタデータ行 `V:proresd3d11dec`、アプリのログに `ProRes: CPU で復号` が無い
3. UI で「無効」を選ぶ → 横に「再起動の後に反映」。`settings.json` に `"proResGpu": "off"`。アプリのログに `ProRes GPU decode setting changed proResGpu=off restartNotice=True`。「自動」へ戻すと案内が消え、ファイルは `"auto"`。もう一度「無効」にして終了
4. 再起動 → UI は「無効」で案内なし。アプリのログ `proResGpu=off を shim に設定しました`、tcs-gst のログ `mode=off source=setting`、ロードで `load.skip profile=prores-gpu reason=prores-gpu-off`、`profile=prores-cpu`、メタデータ行 `V:avdec_prores`、アプリのログに `ProRes: CPU で復号（proResGpu=off、理由は tcs-gst のログ）` がちょうど 1 行（同じ素材を 2 回ロードしても 1 行）
5. `"proResGpu": "bogus"` を手で書いて起動 → アプリのログに `proResGpu の未知の値 'bogus' は auto として扱います` が 1 行、shim には auto（`source=setting`）。UI は「自動」
6. （任意）`TCS_PRORES_GPU=off` を付けて設定は auto で起動 → tcs-gst のログの `source` が環境変数の側になり、UI は「自動」のまま（環境変数は UI に出ない）

## 未解決の点・気づいた点

- **旧い shim との組み合わせ**: `SetProResGpu` はプレイヤー作成の直後に必ず呼ぶので、`tcs_player_set_prores_gpu` の無い DLL（このブランチの今の shim を含む）では `EntryPointNotFoundException` が `EnsurePlayer` から出る。指示書に無いので捕まえていない（段 2 の shim と合わせるまでアプリを起動しない前提）。捕まえるかは親の判断
- **作り直しと「再起動の後に反映」**: `ApplyProResGpu` は `ApplyDecodeMode` と同じく作り直しのたびに設定の現在値を読む。UI で値を変えた後に GPU 復旧の作り直しが起きると、再起動の前に新しい値が shim に渡る（案内は「再起動の後に反映」のまま）。起動時の値に固定するかは親の判断（`decodeMode` は UI が無いので同じ問題は表に出ていない）
- 未知の値の警告は作り直しのたびに 1 行出る（`decodeMode` と同じ振る舞い）
- UI の見た目（ラベルとコンボと案内が 280px 程度の幅に 1 行で収まるか）は、アプリを起動していないので確かめていない。収まらないときは案内が下の行へ折り返す作り
- CPU で開いた記録はデコーダ名 `avdec_prores` だけで判定する。ProRes が decodebin の経路で開いた場合（名前が `decodebin(...)`）は出ない
