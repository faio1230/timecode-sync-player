# M6-c 設計: 他音の混入（分配でプログラム音声が LTC 回線に乗る）（2026-09-19）

**背景（利用者の現場情報）**: 「レコーダーからそのまま抜くこともある。回線が足りない場合は分配する」。
分配・結線の誤りで、**音楽やトーク（プログラム音声）が LTC 回線に混ざる**可能性がある。
M6（広帯域ノイズ）・M6-b（ハム）とは**スペクトルが違う**干渉源で、崖の位置と crest の動きが未知。

**位置づけ**: 0.4.6 候補の crest factor 警告（`docs/analysis/2026-09-19-crest-factor-warning-design.md`）の
**誤検出リスクを埋める測定**。実装はしない（0.4.6 以降の判断材料）。

---

## 1. 狙い

1. **プログラム音声が混ざったとき、LTC はどこで壊れるか。** 同じ SNR（RMS 比）で
   - 広帯域ノイズ: 崖 SNR 5.0→4.5dB（M6）
   - ハム: 崖 SNR 2→1dB（M6-b）
   - **プログラム音声: ?**
   スペクトル依存を確かめる。予想は **hum > program > white** の順に強い（帯域外のエネルギーが多いほど無害）。
   外れたらその方が重要（例: 低域の強い音楽がハム以上に無害/有害など）。
2. **crest factor 警告（しきい値 1.4）がプログラム音声で誤検出しないか。**
   音楽は波高率が高く、**LTC が壊れていないレベルでも crest が 1.4 を超える**可能性がある。
   「crest が 1.4 を超える SNR」と「LTC が壊れる SNR」の距離を測る。
   - 距離が大きい → プログラム音声では警告が早すぎる（誤検出）。警告設計に反映が必要
   - 距離が小さい → 有用な警告としてそのまま使える

## 2. 干渉源モデル（音声アセットはリポジトリに無いので合成）

| 種別 | 生成 | 根拠 |
| --- | --- | --- |
| **pink（音楽/トークの代用）** | 白色ノイズを −3dB/oct の IIR（3 段 1 次）で整形し、RMS を正規化。シード固定 | 音楽・音声の長期スペクトルはおよそ 1/f。白色（平坦）・ハム（単一低域）との中間のスペクトル |
| **speech（トーク風、任意）** | pink に**音節レートのゲート**（例: 4Hz の AM、on 300ms / off 100ms、デューティ 75%）を掛け、長期 RMS を正規化 | トークは無音区間がある。干渉の実効デューティが下がる分、同じ平均 SNR では壊れにくいはず |

- **SNR の定義は M6 と同じ**: プログラムの長期 RMS = LTC 矩形波 RMS × 10^(−SNR/20)。
  （白色・ハムと直接比較できる。）
- ミックス位置は生成直後（ハム・ノイズと同じ場所）。`DirtyLtcSignal` に `ApplyProgram` を追加する。
- ピークは再生経路の正規化（peak>1 で 0.985 にスケール）に任せる。SNR は保存される。
- **実曲・実声は使わない**（アセットを増やさない・ライセンス問題を避ける）。**合成の限界は §7 に明記**。

## 3. 条件の振り方

| run | レベル | 内容 |
| --- | --- | --- |
| P1 pink | clean + SNR **20 / 10 / 6 / 3 / 0** dB | 崖の位置を探索。M6-b と同様に 1 run = 1 条件、phase 切替、各 20 秒 |
| P2 speech（任意） | clean + SNR **10 / 6 / 3** dB | ゲート付き。崖が上がる（＝弱くなる）かの確認 |

- 予想: pink の崖は 2〜4dB の間（hum 1〜2 と white 4.5〜5 の間）。0dB まで壊れなければ追加で −3/−6dB。
- 各 run は 2 本（限界近傍のため）。それでも崖が 2 レベルにまたがるなら、崖詰めを 1 本追加。

## 4. 分析（既存の計器をそのまま使う）

- `analyze-dirty-ltc.py`: レベル別の decode% / clean% / 誤差分布 / gap / gate / seeks。
- `extract-capture-crest.py`: レベル別 crest（peak/rms）。**警告しきい値 1.4 を超える SNR** を読む。
- 報告の中心:
  1. pink の崖 SNR（white 4.5〜5、hum 1〜2 と並べる）
  2. crest が 1.4 を超える SNR と、LTC が壊れる SNR の差（警告の誤検出距離）
  3. speech で崖と crest がどう動くか（任意）
- clean 実測を各 run で取り、相対判定（M6 と同じ）。

## 7. 限界・注意

- **合成干渉源**であり、実曲・実声・実ミックスではない。スペクトル形状（1/f）とゲートだけを模したモデル。
  実素材の過渡（ドラム、子音）やステレオ混入は未モデル。
- 分配の実態（レベル関係、回線のクロストーク量）は現場依存。**試した SNR の範囲を明示**して報告する。
- crest の解釈は 2 秒窓。音楽のダイナミクスで窓ごとのばらつきが M6 より大きい可能性がある
  （`extract-capture-crest.py` は中央値と範囲を出すので、範囲も併記する）。
- 「壊れない」が結論なら、その範囲（例: SNR 0dB まで）をそのまま書く。

## 8. 順序

1. 0.4.5-A フェーズ 2 の実機確認（同期担当）
2. 実機が空いたら P1（2 本）→ 結果を見て P2 / 崖詰め
3. 結果は 0.4.6 候補の crest 警告設計（誤検出距離）に反映
