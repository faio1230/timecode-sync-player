# 0.4.5-B の結果: `SyncOffsetMs` の組み合わせ別推奨値は出せない（2026-09-19）

**指示書**: `docs/prompts/2026-09-19-V045-B-sync-offset-recommendation.md`
**当初の狙い**: 制御ループが見る「報告位置」と現場が見る「表示済みの絵」の差（M3: 固定 −27〜−29ms + σ 11〜12ms）を
素材条件ごとに測り、`SyncOffsetMs` の推奨値を出す。

**結論**: **組み合わせごとの static な推奨値は出せない。**
誤差は位相 φ と整数フレーム欠損 d に分解でき、φ は配置で回転・巡回し、d はばらつきが自身と同程度（1 フレーム幅）だから。
**「出せない」ことが本タスクの成果**である（後述のとおり、当初の M3 数字のまま推奨値を作れば配置が変わるたびに狂う設定を製品に入れていた）。

---

## 1. 誤差の分解: err = (d − φ) · h

現行サンプルクロックの freeze-sweep 21 セル（LTC 24/25/29.97/30 × 映像 24/25/29.97/30/60、配置 0/12/24s）で、
表示 PTS 誤差が次で厳密に表せることを確認した（**モデル最大誤差 0.000000 ms**）。

| 成分 | 定義 | 何で決まるか |
| --- | --- | --- |
| **φ（位相）** | `φ = frac(クリップ内メディア秒 × 映像fps)`。比の位相 `j/q`（q は `映像fps/LTCfps` の既約分母）と配置ずれ `s = frac(offset秒 × 映像fps)` から `φ = frac(j/q − s)` | **組み合わせ（比）と配置の両方**。1:1 は一定、非 1:1 は q 準位の格子を巡回。配置で mod 1 フレーム回転する |
| **d（整数フレーム欠損）** | 表示フレーム − 含むべきフレーム（0 / −1 / −2、まれに +1） | **φ のしきい値と状態**。φ < θ（≈0.35〜0.5）で −1、φ ≥ θ で 0。θ は公開タイミング依存で、同じ φ=0.36 でも run により −1 が 208/270 だったり 43/270 だったりする |
| **h** | 1/映像fps | 組み合わせで決まる |

- 予測 `φ = frac(j/q − s)` は実測 φ と全セル一致（例: 29.97×29.97 の offset 12s は s=0.640 → φ=0.36）。
- 検証 run（29.97 素材×2、LTC29.97 fixed）: offset 0 の clip1 は φ=0 で **−33.37ms 一定（span 0.00）**、
  offset 12s の clip2 は φ=0.36 で **−45.37 / −12.00 の 2 準位（span 33.37）**。
- 分解表（全 21 セル）: `TestResults/v3/m5-ratio-reanalysis/analysis-sync-offset-decomposition.txt`

## 2. なぜ static な推奨値が出せないか

1. **φ は配置で決まり、固定できない。** 非 1:1 では q 準位を巡回し（例 25×60 は 5 準位・間隔 3.33ms）、
   1:1 でも配置の `s` で値が変わる（29.97×29.97: offset 0 は −33.37、offset 12s は −12.00 か −45.37）。
2. **d はばらつきが自身と同程度。** d の範囲は 0〜−2（1〜2 フレーム幅）。
   同じ組み合わせの run 間で median が 1 フレーム動く:
   - 30×60: −31.23 / −15.86（差 15.4ms）
   - 25×60: −28.14 / −18.39（差 9.8ms）
   - 29.97×29.97: −12.00 / −45.37（差 33.4ms）
   指示書の判定規則「変動 σ が固定ぶんと同程度以上なら推奨値を出す意味が無い」に該当する。

## 3. 安定して置ける 3 セルは「組み合わせ」ではなく「配置クラス」

安定なのは 24×24・25×25（どちらも **1:1 かつ φ=0**）と 30×29.97（φ が 0.70〜0.97 の高い窓で d=0 固定）だけ。
つまり安定性を決めているのは LTC×映像の組み合わせではなく、**「φ が一定で d が動かない配置」**である。
24/25 は整数秒のオフセットが常にフレーム格子に乗るため φ=0 を作りやすいが、
29.97/30 系は整数秒オフセットが格子に乗らず、同じ 29.97×29.97 でも置き場所で 1 フレーム動く。

**推奨値として書けるとすれば**、安定 3 セルに限り「+0.9〜1.2 フレーム」相当（24×24 なら +40.0ms、25×25 なら +38.2ms）
だが、これは組み合わせ別ではなく**配置クラス別**の校正値であり、`SyncOffsetMs` の既定値として一般化はできない。

## 4. 代案（0.4.5-B の範囲外）

- **φ はアプリが計算できる**（メディア秒 × 映像fps の端数 − 配置）。動的に扱うなら制御ループの入力変更になる（測定期間外）。
- **d は公開パイプラインの整数フレーム欠損**。パイプライン校正値（1 回の校正で θ を決める）として持つことは可能。
  速度推定の話（M2）とは別の枠組みで、今回の測定だけでは値の一般化はできない。
- どちらも製品変更を伴うため、0.4.5-B では**提案のみ**とし、実施は別タスクとする。

## 5. 当初の M3 数字（固定 −27〜−29ms + σ 11〜12ms）が誤解を招いた理由

- M3 の数字は **1 run 内で 24 / 29.97 / 60fps の 3 クリップをプール**した差（表示−報告）の平均・σ。
  プールすると、各セルの φ と d の混合になり、**「固定成分」に見えるのは混合の中心**だった。
- 実際には各セルは `(d − φ)` の離散値（1:1 は 1〜2 準位、非 1:1 は格子）で、配置が変われば φ が動く。
  「固定 −27〜−29ms」をそのまま `SyncOffsetMs` の既定値にすると、**配置が変わるたびに 1 フレームずれる設定**を製品に入れることになる。
- 分離できたのは、M5 でセル別（LTC×映像）に、そして検証 run で配置別（offset 0/12s）に測ったため。
