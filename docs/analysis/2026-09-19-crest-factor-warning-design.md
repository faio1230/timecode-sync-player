# crest factor 警告の設計（LTC 信号品質）（2026-09-19）

**前提（M6 / M6-b の実測）**
- ノイズの支配量は SNR ひとつ。レベルには独立した効きがない（H1: −6 / −20 / −40dBFS で同一 SNR は同一結果）。
- 広帯域ノイズの崖: SNR 5.0dB 通過 → 4.5dB 全滅。ハム（50/60Hz + 3・5次）の崖: SNR 2dB 通過 → 1dB 全滅。**50/60 で差なし**。
- crest（peak/rms）は clean 1.00 から単調に上がる。**ハムでも上がる**（SNR3 で 1.52）が**飽和が早い**（全滅点で ~1.57）。
- 実測の crest: ハム SNR6=1.44、SNR3=1.52、通過限界 SNR2=1.545、全滅 SNR1=1.562。広帯域は SNR12=1.39、SNR4=1.76。
- 誤検出候補（M6 データ）: B（レベル変化）1.000、D（44.1k→48k）最大 1.020、E（±100ppm）最大 1.027、
  C の 600ms 欠落で **1 窓だけ 1.495**、レベル切替端で **1 窓だけ 4.726**（B の実測）。

**方針**: しきい値は **crest 1.40（ハム基準）**。単発では出さず**持続**で確定する。回復したら**消す**。
実装は 0.4.5-C と同じ「純ロジック + 状態遷移 + 文言」の形。**この文書は設計のみ、実装は別作業。**

---

## 1. 判定規則

| 項目 | 値 | 根拠 |
| --- | --- | --- |
| 指標 | crest = peak / rms（音声コールバックごと） | 既存の `LtcAudioSampleProcessor` が peak/rms を算出済み |
| 発報しきい値 | **crest > 1.40 が連続 2.0 秒** | ハムは SNR≈6dB（崖まで 4〜5dB）、広帯域は SNR≈11dB（崖まで 6dB）で発報。実測の誤検出は最大 1 窓（≈50ms）なので 20 倍の余裕。コールバック間隔は実測 ≈50ms（40 回/2 秒）なので、連続 2.0 秒 ≒ 40 コールバック |
| 解除しきい値 | **crest ≤ 1.35 が連続 2.0 秒** | 発報との間に 0.05 のヒステリシス。境界でのチャタリング防止 |
| peak 下限 | **peak ≥ 0.001（−60dBFS）** の窓だけ評価 | 無音・信号断の窓を除外。−60dBFS は M6 で crest 1.000 が取れた下限（これ未満は現場のノイズフロア支配で指標にならない） |
| 除外窓の扱い | 連続カウントを**リセット** | 信号断は別の表示（NO SIGNAL）が担う。品質警告は「測れているのに汚い」ときだけ |
| 発報遅延 | 最大 約 2 秒 + 次のコールバック | 信号が閾値を跨いでから 2 秒で確定 |
| 解除遅延 | 最大 約 2 秒 + 次のコールバック | 現場で直したら 2 秒で消える |

**しきい値 1.40 の根拠（ハム基準の指定どおり）**: ハム通過限界（SNR2）の crest 1.545 に対し **0.14 の余裕**。
1.5 では余裕が 0.045 しかなく、測定ばらつき（±0.01〜0.02）と区別しにくい。一方 1.4 なら広帯域でも
崖の 6dB 手前で発報するため「早すぎる警告」にならない（実際にノイズが多い状態なので害がない）。

## 2. 誤検出の検討（0.4.5-C の教訓を踏まえて）

| 事象 | 実測 | 本設計での扱い |
| --- | --- | --- |
| レベル変化（B: −60dBFS まで） | crest 1.000 | 影響なし |
| サンプルレート変換（D: 44.1k→48k の線形リサンプル） | 最大 1.020 | 影響なし（本物の SRC は未確認、§6） |
| ppm（E: ±100ppm） | 最大 1.027 | 影響なし |
| 欠落（C: 600ms/5s） | 1 窓だけ 1.495 | 連続 2 秒に届かず**発報しない** |
| **レベル切替端**（信号停止→再開の境界） | **1 窓だけ 4.726** | 同上。**単発で判定しないことが必須**（0.4.5-C の誤検出と同じ形） |
| 定常的なノイズ/ハム | レベル中は crest が持続 | 通過限界より十分手前で発報（意図どおり） |

- 0.4.5-C の失敗（「3 秒キーフレームが来なければ警告」を読み込み位置からの距離で見て、可変 GOP で誤検出）の教訓:
  **1 回の観測で確定しない**。本設計は「2.0 秒連続」で確定し、実測された最長の誤検出（1 窓 ≈50ms）に対し 40 倍の余裕を取る。
  さらに GOP と違い**素材内容に依存しない量**（信号の波形品質）だけを見る。

## 3. 警告のライフサイクル

- **発報**: crest > 1.40 が 2.0 秒連続 → 警告 ON（ログ・トレースに 1 行）。
- **解除**: crest ≤ 1.35 が 2.0 秒連続 → 警告 OFF（ログに 1 行）。**回復したら消える**（利用者の見立てどおり）。
  - 理由: 信号品質は現場で直せる（ケーブル・レベル・接続）。直した結果が画面に出ないと「直ったか」が分からない。
    GOP は素材の性質で現場では直せないためラッチが妥当だが、こちらは条件が変わる量なのでラッチしない。
- **信号断中**: 評価窓が取れないので**状態を保持**（消さない・新たに発報しない）。信号断は既存の NO SIGNAL 表示が担う。
- **繰り返しの劣化**: ヒステリシス（1.40/1.35）と 2 秒の持続で、境界付近の細かい上下ではチャタらない。

## 4. 文言案

- **UI（GOP 警告と同じステータス領域に表示）**:
  - `LTC の信号品質が低下しています（ケーブル・レベル・接続を確認してください）`
- **ログ・トレース**（現場切り分け用。UI には crest の数字を出さない）:
  - 発報: `LTC signal quality degraded crest={Crest:F2} threshold=1.40 durationMs={Duration:F0}`
  - 解除: `LTC signal quality recovered crest={Crest:F2} durationMs={Duration:F0}`
- 補足: GOP 警告は「実測 X.X 秒」を併記しているが、crest は現場になじみがないため UI には出さず、ログに残す案を推奨。
  （併記が必要なら「（実測 crest 1.5）」を足すだけで済む。）

## 5. 実装方針（別作業）

- **純ロジック**: `LtcSignalQualityMonitor`（`LongGopWarningMonitor` と同型）
  - 入力: 音声コールバックごとの `(peak, rms)` と時刻。
  - 状態: `Normal` / `Warning`、連続時間カウンタ、最後の crest。
  - 出力: `None` / `Activated` / `Cleared` の遷移 + `IsWarningActive`。
- **入力点**: `LtcAudioMonitor` は既にコールバックごとに peak/rms を計算している（`LtcAudioSampleProcessor.Process`）。
  集計や窓の追加は不要。モニタを呼び出すだけ。
- **UI**: `SyncViewModel` に品質警告テキストを追加し、`TickLongGopWarning` と同じ tick で更新（別フィールド。ライフサイクルが違うため GOP と混ぜない）。
- **テスト**: 純ロジックの単体テスト（単発スパイクで出ない / 2 秒連続で出る / 回復で消える / ヒステリシス / peak 下限 / 信号断中の保持）。
- **変更範囲**: `src` の追加（モニタ 1 クラス、UI テキスト 1 箇所、呼び出し 1 箇所）。制御則・同期ループには触れない。

## 6. 限界・未確認（実機検証で確認するもの）

- **アナログ回線そのものは未測定**: M6/M6-b はデジタル波形への付加。現場のアナログノイズ・ハム・レベルは
  利用者側の実測待ち（親が預かっている事項）。
- **他の音が混ざる場合**: 音楽・声などが LTC チャンネルに混ざると crest は上がる（複合信号のため）。
  警告は「チャンネルが汚れている」として正しく出る見込みだが、現場での誤検出率は未確認。
- **本物の SRC**（OS/デバイスのサンプルレート変換）: テスト側は線形リサンプル。crest への影響は小さい（1.02）が、
  実機の SRC では未確認。
- **低レベル＋アナログノイズフロア**: 信号が −60dBFS 未満まで落ちてノイズフロアに埋もれると crest が上がる。
  これは「レベル不足」の警告として妥当だが、peak 下限（−60dBFS）で評価外にしているため**警告は出ない**。
  現場で問題になるようなら下限の見直しが必要（H1 の範囲ではレベル低下自体は無害）。

## 7. 実機検証計画（実装後）

1. **オフライン**: 単体テスト（上記）。実機不要。
2. **実機 1〜2 本**（ダーティーハーネスを再利用）:
   - `H2-hum50`（SNR3/2 で crest>1.4、切替端スパイクあり）を流し、**切替端で発報しない**こと・
     **劣化レベルで 2 秒以内に発報**することをアプリログで確認。
   - `B-level`（crest 1.000）を流し、誤発報がないこと。
   - 回復（clean に戻す）で**解除**されることを確認。
   - 見積もり: 2 本 × 約 3 分 ≒ 6〜7 分。
3. 現場の実測値（SNR・ハム量）が得られたら、しきい値 1.40 の妥当性を再確認する。
