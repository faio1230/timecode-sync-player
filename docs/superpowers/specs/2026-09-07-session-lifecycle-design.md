# 同期・描画セッションと終了処理の整理

ユーザー承認: 2026-09-07 の調査で提示した4項目すべてをサブエージェント駆動で実施する指示。

## 目的と方針

時計を差し替え可能にし、LTC受信から同期判断までの制御と描画資源のライフサイクルをMainWindowから移す。最後に終了時の独立した解放処理が例外によって取り残される問題を改善する。

小さなメソッドをさらにEffectsへ分割するだけの案は採用しない。全面的なMVVM移行も対象外。既存Policy/Coordinatorを生かし、状態と処理を責務単位でまとめる。

## 1. 時計

TimecodeSyncServiceとGapFreezeHandlerへTimeProviderを注入し、既定値はTimeProvider.Systemとする。今回の挙動保存では既存UTC時刻の差分と境界条件を保つ。単調時計への移行は別の挙動変更になるため行わない。テストでは時刻を明示的に進め、時間操作のためのprivateフィールドreflectionと実時間1msの境界依存を解消する。ログの内部フィールドを検査する既存テストは必要ならログ出力の検証へ置き換える。

## 2. LTC制御

LTC受信、信号断tick、表示状態、Single/Continue/Gapの分岐、手動制御によるGap退出を共通の制御クラスにまとめる。既存の純粋な判定クラスは再利用する。WPF Dispatcher、ダイアログ、コントロール操作、mpv I/Oは境界として接続する。MainWindowとSyncScenarioHarnessが同じ本番の制御クラスを使い、ハーネス内の重複する判断フローを削除する。表示エラーがtickで上書きされないことを振る舞いで検証し、ソース正規表現テストを置き換える。

## 3. 描画セッション

RenderSessionが専用レンダースレッド、コンテキスト、callback保持、render params、世代、進行中worker、ゲート、バッファと公開処理をまとめて所有する。MainWindowにはWPF固有の表示/Fullscreen接続とGap判断の接続を残せる。既存の描画部品を再利用し、通常/Black/Freezeの直列公開、await後の世代確認、停止後のcallback無効化を保つ。GCによるcallback回収を防ぐフィールド保持、x64 ABIと定数、専用スレッド上のcreate/update/render/freeを変えない。

## 4. 終了処理

依存順序を保ちながら、独立した資源の解放は一つが失敗しても試行する。例外を握りつぶさず収集して呼び出し側へ伝える。進行中のnative workerが終了していない状態で共有バッファやcontextを解放しない。初期化途中と二重Disposeを扱う。DI所有資源をWindowとコンテナ双方が無秩序に解放する設計にはしない。通常終了の動作を維持し、例外時の改善を別コミットとする。

## 検証

基準: Debug build警告0・エラー0、非E2E 1174件合格。各タスクは焦点を絞ったテストと非E2E全件、タスクレビューを実施。最後に実ネイティブDLLを使うFlaUI E2E全件を実行し、LTC実機テストのSkipも結果として明記する。追加テストでは新たな実機依存を導入しない。

## 範囲外

UIデザイン、同期許容値、フレームレート計算、バージョン、プロジェクトファイル形式、ネイティブABI、配布/公開は変更しない。元のmainと未追跡AGENTS.mdを保持する。
