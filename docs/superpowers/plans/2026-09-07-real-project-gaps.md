# 実プロジェクトのGap境界・途中切り替え調査

対象: Videos内の20260518_test.tsp / 20260518_test_2.tsp。元プロジェクトと動画は変更しない。参照素材は1080p H.264、24/60/29.97fps。重なりは既存仕様のプレイリスト上位優先を保つ。

## Task 1: 再現と修正

- Gapから別トラックへ戻る最初のLTCで、新トラックをロードする。古い動画へ誤シーク・再生して次フレーム待ちにしない。
- Freeze取得中でも最新のOnTrack判定、またはBlackへの切り替えを反映し、古いFreeze処理を中断する。
- Sync有効化・同期モード・Gap挙動の変更時は、最後の同期に利用可能だったLTCを再評価する。架空の時刻や新しい信号受信として扱わず、未受信・不正フレーム・手動シーク・信号断による同期抑制を尊重する。
- Gap自身が停止した再生は手動のGap解除で再開する。利用者が停止していた場合や信号断による停止は勝手に再開しない。
- 小さな回帰テストを先に失敗させ、raw LTC（重複・ジャンプを含む）と内部状態の両方を検証する。
- 実機で追加再現したロード/シーク待ちの要求消失には、最新の未完了要求1件だけを再試行する。手動操作で取り消し、先行シークがある場合の見かけ上の許容内も検証する。
- 位置指定ロードおよびEOFからの巻き戻しで、ネイティブの停止とUIの再生意図を一致させる。利用者の停止は保つ。

## Task 2: 実機検証

実プロジェクトを読み取り専用でロードし、VB-CABLE経由のLTCで開始前/開始後/終了前/終了後/重なりの優先順位を検証する。Black/Freeze、Single/Continue、Sync ON/OFFを途中で切り替え、曲・再生位置・画面状態を照合する。元データのハッシュを前後で比較する。個人素材はリポジトリへ追加しない。試験は明示有効化のみとする。

## Task 3: レビュー・回帰確認

独立レビュー、適切な通常テスト、実測結果と元プロジェクトの配置上の注意を文書に残す。境界の論理判定精度と、描画/ロードを含む実機反応時間を区別する。
