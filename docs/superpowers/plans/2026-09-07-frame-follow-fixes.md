# Freeze画像確定・シーク後追従の修正

**Goal:** 前回実測した古いFreeze画像の確定と、シーク後の画像停滞を修正し同じ実画像計測で比較する。
**Architecture:** mpvの描画要求を確実に処理し、実際の描画・コピー完了とFreeze完了状態を結び付ける。下位原因を独立native試験で限定してから必要なスレッド境界を修正する。
**Tech Stack:** .NET8 WPF / libmpv SW render / xUnit / VB-CABLE / Python補助診断。
**Spec:** ユーザーが前回報告を受けて上記2件の修正を明示的に承認。原プロジェクト・元動画を変更しない。常時1ms精度の保証を新設しない。

## 制約・検証基準

- 既存の隔離worktree session-refactor、基準230ba30。main統合・pushはしない。
- 計測用マーカーを製品の同期ロジックに使わない。一般動画で成立する描画完了条件にする。
- 許容幅や抑制時間の数字を根拠なく変更して症状を隠さない。UI停止・破棄時安全性・ネイティブABIを保持。
- 1回目の完全基準ログ TestResults/accuracy/20260907-171342-0f370eb0、2回目の不完全ログも残す。
- 最終検証: 24/29.97/60fps全Freeze末尾画像が正しいこと、4つのシーク試験すべてで250ms区間誤差以内を0.5秒継続して復帰すること、反復で古い画像固定を再現しないこと。これは今回の回帰基準であり、本番SLAではない。
- 欠落入力の測定は不完全として保存。既存の解析閾値・除外条件を弱めない。

## 作業

1. 原因限定: rootが独立native描画pumpとUI依存経路を比較、Freeze/seek担当が現コードとログを追跡。結果に応じて正確な修正契約をledgerへ記録。
2. Freeze: nativeフレーム要求の取りこぼし、描画・コピー未実施でも完了する経路を再現テスト化。成功が伝わった時だけキャッシュを確定し、無効化・失敗を扱う。
3. Seek/描画: 操作待ちでnative描画が止まる依存関係または実証した下位原因を修正。シーク開始/終了・世代・最新要求・手動停止意図を保持。
4. 統合: unit全件、既存E2E、精度2回、乱操作を実施。独立レビュー、前後数値、残る精度の限界をdocs/SYNC-ACCURACY.mdへ記録。日本語コミット。

調査担当はread-onlyで並行。実装は根拠確認後にファイル所有範囲を分けて委任し、rootが共有ビルドと実機を専有する。Task間で共有するRenderSession/MainWindow契約の変更はrootが調整する。
