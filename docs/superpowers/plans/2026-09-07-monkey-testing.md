# VB-CABLE モンキーテスト

目的: 前回リファクタリング版に、乱暴な操作とLTCの断続・ジャンプを組み合わせた再現可能な耐久検証を追加して実行する。

## 制約・合格条件

- 同一seedで操作列とパラメータを再生成できる。操作開始/結果、経過時間、プロセス、メモリ/ハンドル数をファイルへ逐次記録する。実時間の競合まで完全再現できるとは主張しない。
- 実機のCABLE Inputへ生成LTCを送信し、アプリのCABLE Output受信を検証する。前提不足は有効化されたテストでは失敗とする。
- 生存だけでなく、乱操作後の正常LTC再受信、通常再生の復帰、正常終了を検証する。
- 長時間試験は明示指定のみ。通常テストではスキップ。テスト対象外のデスクトップ操作や音声設定の変更はしない。
- アプリ設定は既存E2Eヘルパーで隔離。強制終了は起動した試験プロセスツリーに限定し、タイムアウトを失敗として保存。
- 自動生成動画の結果を本番素材・Spout受信先まで検証済みと扱わない。

## Task 1: seed付き実機乱操作テスト

新規 `MonkeyStressE2ETests` と必要な専用ヘルパー。既存 `E2EAppRunner`、`LtcSignalPlayer`、`TestVideoFactory` を再利用する。再生/停止、シーク連打、曲切り替え、同期とモニターの切り替え、同期/ギャップ/信号断モード、LTC停止/再開/ジャンプ/ノイズを扱う。UIAによりアプリのコントロールだけ操作する。初期と最終にLTC進行を確認し、最後に通常再生を確認、信号受信・描画中の正常終了を検証する。

環境変数契約: `TIMECODE_MONKEY_ENABLED=1`、`TIMECODE_MONKEY_SEED`(int)、`TIMECODE_MONKEY_ACTIONS`(1..100000)、`TIMECODE_MONKEY_REPORT_DIR`(絶対パス)。Category=Monkey と E2E、Collection=E2E。既定未有効化はスキップ。ログ名は `monkey.jsonl` と最終 `summary.json`、summaryには成功/失敗と実行済み操作数を含める。再現性を損なう状態依存の乱数消費をしない。

## Task 2: 実行監視・手順書

`scripts/run-timecodesyncplayer-monkey.ps1`: seed列、操作数、1回の上限分数、結果先を指定。対象EXEを明示、ビルド後にMonkeyのみを直列実行。各seed専用フォルダにTRX、標準出力/エラーとJSONLを保存。総時間上限で自身のテストプロセスツリーだけ停止して失敗にする。未実行/スキップ/summary欠落を成功扱いにしない。環境変数を呼び出し元へ残さない。

`docs/MONKEY-TESTING.md`: 実行・同seed再実行、必要なVB-CABLE接続と本番素材の準備、ログの見方、テストの範囲と限界。

## Task 3: 実行とレビュー

短い接続確認後、異なるseedで計750操作以上を実施。障害があれば再現・原因特定・回帰テストを行う。独立レビューで偽陽性/ハング検出/終了の証拠を確認し、通常テストも実行。実測結果を手順書へ記録する。
