### 実行

| ラベル | 素材 | フィルター | ReportDir |

窓は `harness.jsonl` の `scenario-start` と `app-exit`（UTC）。アプリログのローカル時刻（+09:00）へ直し、
`<ReportDir>/app-logs/timecodesyncplayer-*.log` のその窓の行だけを数える（`scripts/analyze-v054-gates.py`）。
2 周の重なりは無し（スクリプトが検査）。

### 数え方（門ごとの対）

- 1: `sync.gate signal-loss-confirm` の `elapsedMs`（直前の有効フレーム→確定）。
- 2: 直前の `LTC frame diagnostic status="Jump"` → `SignalRecovered source=held-jump`。
- 3: `Jump dropped` 行 → 次の `applying the … frame once`。
- 4: `holding unconfirmed Jump frame` 行 → 次の `applying the confirmed Jump frame once`。
- 5: `sync.gate pending-suppress` の行数（発火＝フレーム）。遅延は連続する抑止行（間隔 ≤1s）の
  先頭→最後（抑止が続いた区間）。
- 6: `sync.gate seek-settled` の `elapsedMs`（シーク発行→セトル確定。200ms cooldown を含む）。
- 7: `sync.gate pending-timeout` の `elapsedMs`。
- 8: `sync.gate pending-replace` の行数（discard は `pending "Superseded"` を別掲）。
- 9: `sync.gate post-settle-suppress` の `elapsedMs`（直前の着地からの経過）。
- 10: 発火＝シーク発行行（同期 2 種・着地・Jump 補正）。遅延は次の決着行（settle / timeout /
  trust-reacquire）まで。
- 11: `pending "TimedOut"` / `"Superseded"` → `sync.gate trust-reacquire`。
- 12: `sync.gate untrusted-defer` の行数（発火＝フレーム）。遅延は連続区間（間隔 ≤0.5s）の先頭→最後。
- 13: `Timecode sync seek gated` → 次のシーク発行。
- 14: `seek-debounce` / `seek-skip reason="Debounced"` の行数。遅延は連続区間の先頭→最後。
- 15: `rate catch-up preferred` の回数。遅延は `settled` の `elapsedSeconds`。
- 16: `landing window closed …`（理由別）の `ageMs`（＝窓が開いていた時間）。
- 17: `sync.gate load-suppress` の `elapsedMs`（ロード開始からの経過）。
- 18: `sync.gate load-release` の `elapsedMs`（ロード開始→解除）。`file load released` は timeout/forced。
- 19・21: 発火行の回数のみ（遅延 0 の門）。
- 20: `landing skipped (clip boundary hold active)` の回数。遅延はそのホールドの解除まで。
- 22: `native-seek-defer` の行数（ネイティブ）。手動は `Sync lifecycle: "ManualSeek"` を別掲。
- 23: `Smooth rate limit switched … active` → 次の `ended`（≤1.5s の対だけを窓の長さとする）。
- 24: `Jump correction limit reached` の回数（`Jump correction seek` を別掲）。

§9 の指標（同期シーク・着地シーク・時間切れ・通り過ぎの戻し・発振・着地の遅れ・黒フレーム・
R-1/R-2 の一時停止）は `v0.5.3-d38-seek-gates.md` §9 と同じ定義で、アプリログと `harness.jsonl` から数えた。

- 同期+着地シーク: `Timecode sync seek .*success=true` / `Continue mode: sync seek .*success=true` /
  `LTC timecode held: landing seek issued`。
- 通り過ぎの戻し: 着地シークが直前の同期シークから 500ms 以内・目標差 0.25 秒以内のもの。
- 発振: 直前 2 本と同じ目標（±0.04 秒）へ 1 秒以内の 3 本目以降。
- 着地の遅れ: `hold-landing.landingLatencySeconds`（テストが記録。n は値のある回数）。
- 黒フレーム: `jump-black-summary` の `blackFrames` / `samples`。
- R-1/R-2: `hold-pause.pauseLatencySeconds`（試験、UIA 読み）と、アプリログの連続 Duplicate の
  先頭→`LTC signal lost: playback paused`。無音（`reason="SignalLoss"`）で止まった回は
  先行 Duplicate が無いので N/A（重い素材の R-2 はこの型）。
