## 3. 利用者の一時停止の扱い

- 利用者の操作は、`PlaybackControlState.IsPaused`（UI とアイコン）を変えるだけで、**どの持ち主の集合にも記録されていない**（#12）。
- 他の持ち主が再開するとき、利用者が止めていても今はそのまま再開する（#13）。例外は、
  (a) 位置つきロードが `keepPaused` で利用者の状態を引き継ぐ（#14）、
  (b) ギャップ進入時に既に一時停止ならギャップは pause を持たない（#6 の `RecordPauseOwnership`）、
  (c) ギャップ出口で `wasPaused` を復元する（#9）の 3 か所だけ。
- 利用者が止めている間に他の持ち主の再開が来る具体例: 利用者が一時停止 → 範囲外 LTC で境界ホールド →
  LTC が範囲内へ戻る → `SetEndHold(false)` が `SetPaused(false)` を呼び、利用者の一時停止が解除される
  （赤テスト `BoundaryHoldRelease_WhileUserPaused_DoesNotResumePlayback`）。

## 4. ギャップと境界ホールドが同時に成立しない理由

境界ホールドは Single モードの経路（`SingleModeSyncCoordinator.Apply` / `ApplyClipBoundaryHoldOnly`）でしか
評価されず、ギャップ状態は「Sync ON かつ Continue」でしか維持しない（`GapStateExitPolicy.ShouldExit`、
`LtcSyncController.ExitGapForManualControl`）。Single へ切り替えるとギャップは解除されるため、
「境界ホールドの解除」と「ギャップの解除」が同じ再開として重なる場面は無い。
（Single → Continue の切替で `BoundaryHoldState` が残るのは §6 の 1 の寿命の問題で、Continue では
`ReleaseBoundaryHold` が呼ばれないため、12 の再開経路としては重ならない。）

## 所見（集合をどこに当てるか）

1. **境界ホールドの解除（#5）だけに当てる場合**: 変わるのは §6 の 12 そのもので、赤テスト 2 件が緑になる。
   他の再開（#2 信号断・#7/#8 ギャップ・#11 プロジェクト復元・#12 利用者）は今の条件のまま。
2. **全部の再開経路に当てる場合**: 上に加えて、#2・#7・#8・#11 が「他持ち主が止めていれば再開しない」に変わり、
   #14 のロード再開と #17 のシーク後の再主張も集合を見る必要が出る（変わる経路が 5 つ以上増える）。
3. 具体的に変わる場面: 信号断復帰時に境界ホールド/プロジェクト復元/利用者が残っている、ギャップ解除時に
   利用者・プロジェクト復元が止めている（#8 は信号断だけ既に見る）、プロジェクト復元解除時に利用者が
   止めている、の 3 系統。
4. リスク: 集合に「利用者」を入れるには操作入口での記録が要る（#12）。記録を忘れた経路（位置なしロード #14、
   シーク後 #17、停止 #16）は利用者の意思を落とすため、全部に当てるなら先に入力の棚卸しが必要。
5. 勧め: v0.5.2 は「集合の導入＋#5 を集合経由に」に絞り、#2・#7・#8・#11 は今の条件のまま集合を照会する形に
   写す（振る舞いを変えない）。これで「変わってよいのは 12 だけ」に収まる。

## 親の判断と 2g-2 の範囲（2026-09-25）

表と所見を承認した。所見 5 の勧めのとおり、v0.5.2 は**集合を当てるのを境界ホールドの解除（#5）だけ**にする。

- **集合は新しい状態として持たない。** 各持ち主の今の記録から組み立てる（信号断 `_pausedByPolicy` / ギャップ `_pauseOwnedByGap` /
  プロジェクト復元 `IsPending` / 境界ホールド `IsHeld`）。集合を別に持つとそれ自体が新しいラッチになり、記録とずれうるため
- #5 は「境界ホールド以外の持ち主が 1 つでもあれば再開しない」。#2・#7・#8・#11 などほかの再開は今の条件のまま
- **利用者は v0.5.2 では持ち主に入れない。** 入れるには操作の入口での記録と、位置なしロード（#14）・シーク後（#17）・停止（#16）での
  下ろし方を先に決める必要がある（所見 4）。漏れると利用者の意思とずれた状態が残る。利用者側の赤いテストは Skip のまま、
  v0.5.3 の候補（設計書 §6 の 15）にする
- ギャップと境界ホールドは同時に成立しない（§4）ので、#5 で実際に効くのは信号断（とプロジェクト復元）
