## 所見（経路ごとの判断）

1. **#1 GPU 復旧: 通してよい。** 9 行すべてが消えるのが望ましく（とくに Single の 6・7）、
   着地窓と 1 回再適用は復旧後の追従に効く。解除条件も再生が続くので満たせる。
2. **#2 自動送り（MediaIn > 0）: 通してよい。** MediaIn = 0 の経路（今も通る）と揃う。ただし同期 OFF の
   経路で `Sync lifecycle: FileLoad` の列が増える点だけ、ログ解析への影響を確認する。
3. **#3 ギャップの `LoadPausedAt`: 通すと自分の処理が壊れる。** 一時停止のままなのでロード解除が
   最大 5 秒後になり、全シーク抑止と着地窓がギャップ明けと重なる。ギャップ用に「`loadingFile` を
   立てずに、保留・位置の信頼・読み込み番号だけを切る」別の口が要る。
4. **#4 Freeze の読み直し: 3 と同じ理由で通すと壊れる。** 加えて 1 秒ごとに繰り返すので、
   `FileLoad` のできごと（ログ・クリア）を繰り返さない扱いが要る。
5. **#5 トラック切替（参考）: 判断が要る。** 今も通っている。`LoadFile` に一律で通すなら、
   `ContinueOnTrackCoordinator` の明示呼び出しとの二重を先に解消する（どちらか 1 か所に寄せる）。

## 段 3b の結果（2026-09-26）

- #1 GPU 復旧と #2 自動送り（MediaIn > 0）を、読み込み成功の後に `BeginFileLoad`（source `gpu-recovery` / `auto-advance`）へ通した。
  `PlaybackOperationsCoordinator.LoadFile` の共通の入口には入れていない（#5 の二重を避ける）。MediaIn = 0 の自動送りで FileLoad が 1 回だけのことをテストで固定
